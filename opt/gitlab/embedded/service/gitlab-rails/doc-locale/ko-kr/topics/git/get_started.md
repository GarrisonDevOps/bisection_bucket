Git은 코드 변경 사항을 추적하고 다른 사람들과 협업하기 위해 사용하는 버전 관리 시스템입니다. GitLab은 CI/CD 및 소프트웨어 개발 수명 주기를 관리하는 데 도움이 되는 기타 기능을 제공하는 웹 기반 Git 리포지토리 관리자입니다.

## 리포지토리 {#repositories}

Git 리포지토리는 프로젝트의 모든 파일, 폴더 및 버전 기록을 포함하는 디렉터리입니다. 코드 변경 사항을 관리하고 추적하는 중앙 허브 역할을 합니다.

Git 리포지토리를 초기화하거나 기존 리포지토리를 복제하면 Git은 프로젝트 디렉터리 내에 `.git` 숨김 디렉터리를 만듭니다. 이 디렉터리는 Git이 리포지토리를 관리하기 위해 사용하는 모든 필수 메타데이터와 객체를 포함하며, 파일에 대한 모든 변경 사항의 완전한 기록도 포함합니다. Git은 파일 수준에서 변경 사항을 추적하므로 시간 경과에 따라 개별 파일에 대한 수정 사항을 볼 수 있습니다.

자세한 내용은 [리포지토리](../../user/project/repository/_index.md)를 참조하세요.

## 작업 디렉터리 {#working-directories}

작업 디렉터리는 코드를 변경하는 위치입니다. Git 리포지토리를 복제하면 작업 디렉터리에 리포지토리의 로컬 복사본을 만듭니다. 파일을 편집하고, 새 파일을 추가하고, 코드를 테스트할 수 있습니다. 협업하려면 다음을 수행할 수 있습니다:

- 커밋: 작업 디렉터리에서 변경 사항을 만든 후 해당 변경 사항을 로컬 리포지토리에 커밋합니다.
- 푸시: GitLab에서 호스팅되는 원격 Git 리포지토리로 변경 사항을 푸시합니다. 이렇게 하면 다른 팀 멤버가 변경 사항을 사용할 수 있습니다.
- 풀: 원격 리포지토리에서 다른 사용자가 만든 변경 사항을 풀하고, 로컬 리포지토리가 최신 변경 사항으로 업데이트되었는지 확인합니다.

자세한 내용은 [일반 Git 명령어](commands.md)를 참조하세요.

## 브랜치 {#branches}

Git에서 브랜치를 사용하여 서로 간섭하지 않으면서 동시에 다양한 기능, 버그 수정 또는 실험에 대해 작업할 수 있습니다. 브랜칭을 통해 고립된 환경을 만들어 기본 브랜치에 영향을 주지 않으면서 변경 사항을 만들고 테스트할 수 있습니다. GitLab에서 기본 브랜치는 일반적으로 `main`라고 불립니다.

### 브랜치 병합 {#merge-a-branch}

기능이 완성되거나 버그가 수정된 후에는 브랜치를 기본 브랜치로 병합할 수 있습니다. 이는 [머지 리퀘스트](../../user/project/merge_requests/_index.md)에서 수행할 수 있습니다. 병합은 변경 사항의 기록을 보존하면서 한 브랜치의 변경 사항을 다른 브랜치로 가져오는 안전한 방법입니다.

예를 들어 두 브랜치에서 동일한 코드 줄을 수정한 경우 GitLab은 이를 [머지 충돌](../../user/project/merge_requests/conflicts.md)로 표시합니다. 이는 코드를 검토하고 편집하여 수동으로 해결해야 합니다.

### 브랜치 삭제 {#delete-a-branch}

성공적으로 병합한 후에 필요 없으면 브랜치를 삭제할 수 있습니다. 불필요한 브랜치를 삭제하면 리포지토리를 구성하고 관리할 수 있습니다.

> [!note]
> 작업 손실을 방지하려면 최종 병합 후 브랜치를 삭제하기 전에 모든 변경 사항이 기본 브랜치에 통합되었는지 확인하세요.

자세한 내용은 [브랜치](../../user/project/repository/branches/_index.md)를 참조하세요.

## Git 워크플로우 이해 {#understand-the-git-workflow}

Git 워크플로우를 사용하여 코드를 관리하고, 다른 사용자와 협업하고, 프로젝트를 구성할 수 있습니다. 표준 Git 워크플로우에는 다음 단계가 포함됩니다:

1. 리포지토리 복제: 리포지토리를 머신에 복제하여 로컬 복사본을 만듭니다. 원본 리포지토리에 영향을 주지 않으면서 프로젝트에서 작업할 수 있습니다.
1. 새 브랜치 생성: 변경 사항을 만들기 전에 새 브랜치를 생성하는 것이 좋습니다. 이렇게 하면 변경 사항이 고립되어 다른 사용자의 기본 브랜치에 대한 작업을 방해하지 않습니다.
1. 변경 사항 수행: 작업 디렉터리의 파일에 변경 사항을 수행합니다. 새로운 기능을 추가하고, 버그를 수정하거나, 다른 수정 사항을 수행할 수 있습니다.
1. 변경 사항 스테이징: 파일에 변경 사항을 만든 후 커밋할 변경 사항을 스테이징합니다. 스테이징은 다음 커밋에 포함될 변경 사항을 Git에 알려줍니다.
1. 변경 사항 커밋: 스테이징된 변경 사항을 로컬 리포지토리에 커밋합니다. 커밋은 작업의 스냅샷을 저장하고 파일 변경 사항의 기록을 만듭니다.
1. 변경 사항 푸시: 변경 사항을 다른 사용자와 공유하려면 원격 리포지토리로 푸시합니다. 이렇게 하면 다른 협력자가 변경 사항을 사용할 수 있습니다.
1. 브랜치 병합: 변경 사항을 검토하고 승인한 후 브랜치를 기본 브랜치로 병합합니다. 예를 들어, `main`입니다. 이 단계는 변경 사항을 프로젝트에 통합합니다.

## 포크 {#forks}

특히 오픈소스 프로젝트로 작업하는 일부 조직에서는 다양한 워크플로우를 사용할 수 있습니다. 예를 들어 [포크](../../user/project/repository/forking_workflow.md)입니다.

포크는 자신의 네임스페이스에 존재하는 리포지토리의 개인 복사본입니다. 오픈소스 프로젝트에 기여하거나 팀이 중앙 집중식 리포지토리를 사용할 때 이 워크플로우를 사용합니다.

## Git 설치 {#install-git}

Git 명령어를 사용하고 GitLab 프로젝트에 기여하려면 컴퓨터에 Git 클라이언트를 다운로드하여 설치해야 합니다.

설치 프로세스는 운영 체제에 따라 다릅니다. 예를 들어 Windows, macOS 또는 Linux입니다. Git을 설치하는 방법에 대한 자세한 내용은 [Git 설치](how_to_install_git/_index.md)를 참조하세요.

## Git 명령어 {#git-commands}

명령줄에서 Git과 상호작용하기 위해 Git 명령어를 사용할 수 있습니다:

- `git clone`: 리포지토리를 로컬 머신으로 복제합니다.
- `git branch`: 로컬 리포지토리의 브랜치를 나열, 생성 또는 삭제합니다.
- `git checkout`: 로컬 리포지토리의 여러 브랜치 간에 전환합니다.
- `git add`: 커밋할 변경 사항을 스테이징합니다.
- `git commit`: 스테이징된 변경 사항을 로컬 리포지토리에 커밋합니다.
- `git push`: 로컬 커밋을 원격 리포지토리로 푸시합니다.
- `git pull`: 원격 리포지토리에서 변경 사항을 가져오고 로컬 브랜치로 병합합니다.

더 포괄적인 정보와 자세한 설명은 [일반 Git 명령어](commands.md) 가이드를 참조하세요.

### Git과 SSH 사용 {#use-ssh-with-git}

원격 리포지토리로 작업할 때 안전한 통신을 위해 SSH를 사용해야 합니다.

GitLab은 SSH 프로토콜을 사용하여 Git과 안전하게 통신합니다. SSH 키를 사용하여 GitLab 원격 서버에 인증하면 매번 사용자 이름과 비밀번호를 입력할 필요가 없습니다.

GitLab과 함께 SSH를 사용하려면 다음을 수행해야 합니다:

1. 로컬 시스템에서 SSH 키 쌍을 생성합니다.
1. GitLab 계정에 SSH 키를 추가합니다.
1. GitLab으로의 SSH 연결을 확인합니다.

자세한 내용은 [GitLab과 함께 SSH 키 사용](../../user/ssh.md)를 참조하세요.
