사용자를 위한 GitLab 규정 준수 기능은 GitLab 그룹과 프로젝트가 일반적인 규정 준수 표준을 충족하도록 보장합니다.

## 규정 준수를 위한 워크플로우 자동화 {#compliant-workflow-automation}

규정 준수 팀이 자신의 제어 및 요구사항이 올바르게 설정되어 있다는 확신을 갖고, 또한 설정된 상태가 유지되도록 하는 것이 중요합니다. 이를 수행하는 한 가지 방법은 설정을 주기적으로 수동으로 확인하는 것이지만, 이는 오류가 발생하기 쉽고 시간이 많이 걸립니다. 더 나은 방법은 단일 정보 원본 설정과 자동화를 사용하여 규정 준수 팀이 구성한 항목이 구성된 상태로 유지되고 올바르게 작동하도록 하는 것입니다. 다음 기능을 사용하면 규정 준수를 자동화할 수 있습니다:

| 기능                                                                                                                                  | 인스턴스                            | 그룹                               | 프로젝트                             | 설명 |
|:-----------------------------------------------------------------------------------------------------------------------------------------|:-------------------------------------|:-------------------------------------|:-------------------------------------|:------------|
| [규정준수 프레임워크](compliance_frameworks/_index.md)                                                                      | {{< no >}} | {{< yes >}} | {{< no >}} | 프로젝트가 따라야 하는 규정 준수 요구사항의 유형을 설명합니다. |
| [규정 준수 파이프라인](compliance_pipelines.md)                                                                                 | {{< no >}} | {{< yes >}} | {{< no >}} | 주어진 규정 준수 프레임워크가 있는 모든 프로젝트에 대해 실행할 파이프라인 구성을 정의합니다. |
| [병합 요청 승인 정책 승인 설정](../application_security/policies/merge_request_approval_policies.md#approval_settings) | {{< yes >}} | {{< yes >}} | {{< yes >}} | GitLab 인스턴스 또는 그룹 전체의 모든 적용된 그룹 또는 프로젝트에서 여러 승인자를 적용하고 다양한 프로젝트 설정을 재정의하는 병합 요청 승인 정책을 적용합니다. |

## 감사 관리 {#audit-management}

모든 규정 준수 프로그램의 중요한 부분은 무엇이 일어났는지, 언제 일어났는지, 누가 책임이 있는지 파악할 수 있는 것입니다. 감사 상황뿐만 아니라 문제 발생 시 근본 원인을 파악하기 위해 이를 사용할 수 있습니다.

저수준의 원본 감사 데이터 목록과 고수준의 요약 감사 데이터 목록을 모두 보유하는 것이 유용합니다. 이 두 가지를 통해 규정 준수 팀은 문제가 존재하는지 빠르게 파악한 다음 해당 문제의 세부사항을 자세히 살펴볼 수 있습니다. 다음 기능을 사용하면 GitLab에 대한 가시성을 제공하고 어떤 일이 일어나고 있는지 감사할 수 있습니다:

| 기능                                           | 인스턴스                            | 그룹                               | 프로젝트                             | 설명 |
|:--------------------------------------------------|:-------------------------------------|:-------------------------------------|:-------------------------------------|:------------|
| [감사 이벤트](audit_events.md)                   | {{< yes >}} | {{< yes >}} | {{< yes >}} | 코드 무결성을 유지하기 위해 감사 이벤트는 관리자에게 고급 감사 이벤트 시스템에서 GitLab 서버에 대한 모든 수정 사항을 볼 수 있는 기능을 제공하므로 모든 변경사항을 제어, 분석 및 추적할 수 있습니다. |
| [감사 보고서](audit_events.md)                  | {{< yes >}} | {{< yes >}} | {{< yes >}} | 발생한 감사 이벤트를 기반으로 보고서를 생성하고 액세스합니다. 미리 빌드된 GitLab 보고서 또는 API를 사용하여 자신만의 보고서를 빌드합니다. |
| [감사 이벤트 스트리밍](audit_event_streaming.md) | {{< yes >}} | {{< yes >}} | {{< yes >}} | GitLab 감사 이벤트를 HTTP 엔드포인트 또는 AWS S3 또는 GCP Logging과 같은 타사 서비스로 스트리밍합니다. |
| [규정 준수 센터](compliance_center/_index.md)  | {{< no >}} | {{< yes >}} | {{< yes >}} | 규정 준수 표준 준수 보고 및 위반 보고서를 통해 조직의 규정 준수 태세에 대한 가시성을 빠르게 확보합니다. 그룹 규정 준수 프레임워크를 중앙에서 관리합니다. |

| 기능                                                                                                                                                                                                                                                                | 인스턴스                            | 그룹                               | 프로젝트                             | 설명 |
|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:-------------------------------------|:-------------------------------------|:-------------------------------------|:------------|
| [세분화된 사용자 역할<br/>및 유연한 권한](../permissions.md)                                                                                                                                                                                                  | {{< yes >}} | {{< yes >}} | {{< yes >}} | 5가지 서로 다른 사용자 역할과 외부 사용자 설정으로 액세스 및 권한을 관리합니다. 리포지토리에 대한 읽기 또는 쓰기 액세스 권한이 아니라 사람의 역할에 따라 권한을 설정합니다. 이슈 추적기에만 액세스해야 하는 사람들과는 소스 코드를 공유하지 마세요. |

| [푸시 규칙](../project/repository/push_rules.md)                                                                                                                                                                                                                      | {{< yes >}} | {{< yes >}} | {{< yes >}} | 리포지토리에 대한 푸시를 제어합니다. |

[업무 분리 배포 프로젝트](https://gitlab.com/guided-explorations/separation-of-duties-deploy/blob/master/README.md)와 [업무 분리 프로젝트](https://gitlab.com/guided-explorations/separation-of-duties/blob/master/README.md)에서 이 설정을 사용하여 이러한 역할을 정의하는 방법을 확인하세요. |
