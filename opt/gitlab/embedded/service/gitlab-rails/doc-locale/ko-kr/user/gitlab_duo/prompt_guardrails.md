GitLab Duo에는 기초 프롬프트 가드레일이 있습니다. 이러한 가드레일은 구조화된 프롬프트, 적용된 컨텍스트 경계 및 필터링 도구에 의존하며, 다음을 지원합니다:

- 민감한 데이터 노출 감소.
- 프롬프트 인젝션 방지.
- 모델을 안전하고 도움이 되는 응답으로 유도합니다.

이러한 보안 조치는 GDPR과 같은 일반적인 규제 표준을 준수하는 데 도움이 되며, AI 기반 워크플로우와 관련된 위험을 최소화하는 데 도움이 됩니다.

> [!note]
> 이러한 가드레일이 위험을 줄일 수 있지만 모든 취약점을 제거하지는 않습니다. 어떤 시스템도 모든 오용이나 정교한 공격으로부터 완벽한 보호를 보장할 수 없습니다.

## 일반 가드레일 {#general-guardrails}

GitLab Duo에서 사용하는 프롬프트의 목표는 다음과 같습니다:

- 허용되지 않는 콘텐츠 피하기: 모델은 유익하고 정중하게 행동하고 증오적이거나 비난적인 언어를 피하도록 지시됩니다.
- 사용자 요청을 엄격히 준수: 모델은 프롬프트를 밀접하게 따르고 역할 연기, 사칭 또는 관련 없는 콘텐츠로의 편향을 피하도록 지시됩니다.
- 태그를 사용하여 콘텐츠 격리: 태그는 모델에게 제공된 스니펫에 집중하도록 지시하여 프롬프트 인젝션의 위험을 줄이는 데 도움이 됩니다.
- 비밀 필터링: 코드 제안을 스캔하여 민감한 정보를 실수로 전송하는 것을 방지합니다. 예: 고객의 민감한 구성 데이터를 포함하는 작업 로그는 `<log>` 태그에 캡슐화되어 모델이 제공된 컨텍스트에만 집중하고 관련 없는 가정을 하지 않도록 하는 데 도움이 됩니다.

## 직무 역할별 가드레일 {#guardrails-by-job-role}

역할에 따라 GitLab Duo를 위해 설정된 가드레일에 대해 다른 우려 사항이 있을 수 있습니다.

### 기술 사용자 {#for-technical-users}

- **코드 격리**: `<selected_code>`, `<git_diff>` 및 `<log>`과 같은 태그는 모델이 제공한 코드 또는 콘텐츠에 엄격하게 집중하도록 권장하여 프롬프트 인젝션의 위험을 줄이는 데 도움이 됩니다.
- **비밀 필터링**: Gitleaks와 같은 도구는 코드 제안을 스캔하여 API 키 또는 비밀번호와 같은 민감한 데이터가 공유되는 것을 방지합니다.
- **집중된 응답**: GitLab Duo는 도움이 되지 않거나 예상치 못한 출력으로 이어질 수 있는 동작을 피하는 데 도움이 되는 주제에 집중합니다.
- **근본 원인 분석**: 문제를 해결할 때 GitLab Duo는 제공된 작업 로그만 분석하고 제공된 내용 이상으로 가정하지 않도록 합니다.

### 감시자 및 규정 준수 팀 {#for-auditors-and-compliance-teams}

- **규제 정렬**: 이 시스템은 데이터 유출과 같은 위험을 줄이는 데 도움이 되며, 조직이 GDPR과 같은 표준을 준수하도록 도움이 됩니다.
- **투명성**: 프롬프트와 컨텍스트가 구조화되는 방식은 GitLab Duo 작업을 예측 가능하고 감사에 사용 가능하도록 하는 데 도움이 됩니다. 자세한 내용은 [기능별 가드레일](#guardrails-for-features)을 참조하세요.
- **콘텐츠 제어**: 논의 요약 또는 취약점 해결과 같은 작업의 경우, GitLab Duo는 제공된 입력만 사용하여 오류 또는 의도하지 않은 출력의 가능성을 줄입니다.
- **악의적인 입력으로부터의 보호**: 필터 및 태깅 메커니즘은 시스템을 해로운 또는 형식이 잘못된 사용자 콘텐츠로부터 보호하는 데 도움이 됩니다.

### 의사 결정자 {#for-decision-makers}

- **신뢰 구축**: 보안 조치는 GitLab Duo가 책임감 있게 행동하는지 확인하는 데 도움이 되며, 이는 새로운 도구에 대한 신뢰에 중요합니다.
- **정보에 입각한 결정**: 보안 기능에 대한 명확한 문서는 조직에 대한 GitLab Duo의 적합성을 평가하는 데 필요한 정보를 제공합니다.
- **위험 감소**: 민감한 데이터와 모델 동작에 관한 일반적인 우려 사항을 해결하기 위해 노력함으로써 GitLab Duo는 AI를 워크플로우에 통합하기 위한 안전하고 실용적인 솔루션을 제공합니다.

## 기능별 가드레일 {#guardrails-for-features}

개별 기능에는 노출을 제한하기 위한 특정 프롬프트 지시사항이 포함됩니다. 프롬프트 지시사항은 다음 원칙을 따릅니다.

### GitLab Duo Agent Platform {#gitlab-duo-agent-platform}

프롬프트 인젝션을 방지하기 위해 신뢰할 수 없는 콘텐츠를 격리합니다.

AI 게이트웨이에서 [프롬프트 인젝션 시도를 감지](../duo_agent_platform/security_threats.md#detect-prompt-injection-attempts)하고 기록하거나 차단합니다.

### GitLab Duo Chat {#gitlab-duo-chat}

응답은 주제에 맞고 건설적이며 비학대적이어야 합니다. 성격 변화, 역할 연기 또는 악의적인 지시는 권장되지 않습니다. 사용자 제공 콘텐츠에 집중하면 인젝션 위험을 줄이는 데 도움이 됩니다.

### 토론 요약 {#discussion-summary}

댓글은 요약되고 잠재적으로 악의적인 콘텐츠와의 상호 작용은 권장되지 않습니다. 사용자는 의심스러운 댓글에 대해 경고를 받아야 하지만 이를 공개하거나 복제하지 않습니다.

### 코드 설명, 테스트 생성, 코드 리팩터, 코드 수정 {#code-explanation-test-generation-refactor-code-fix-code}

태그를 사용하여 코드를 포함하고 모델의 집중력을 제한하여 모델이 외부의 확인되지 않은 지시사항이나 콘텐츠를 고려하지 않도록 방지합니다.

### CLI용 GitLab Duo {#gitlab-duo-for-cli}

자연어에서 Git 명령을 생성하는 작업을 프레임화하여 범위와 해로운 출력의 위험을 제한합니다.

### 머지 리퀘스트 요약 {#merge-request-summary}

프롬프트 인젝션을 방지하기 위해 코드를 격리합니다.

### 코드 검토 {#code-review}

프롬프트 인젝션을 방지하기 위해 코드를 격리합니다.

### 머지 커밋 메시지 생성 {#merge-commit-message-generation}

태그를 사용하여 모델이 참조할 수 있는 콘텐츠를 격리하고 제한합니다.

### 근본 원인 분석 {#root-cause-analysis}

태그를 사용하여 제공된 작업 로그에만 엄격하게 집중하고 주어진 데이터 이상의 가정을 방지합니다.

### 취약성 해결 {#vulnerability-resolution}

의도된 기능을 변경하지 않으면서 보안 문제를 해결하도록 권장합니다. 모델은 코드 변경을 방지하기 위해 제공된 코드 diff에 집중하도록 지시됩니다.
