title: 파일 잠금

파일 잠금을 사용하면 여러 사람이 동시에 같은 파일을 편집하지 못하므로 머지 충돌을 방지할 수 있습니다. 파일 잠금은 설계 파일, 동영상 및 기타 텍스트가 아닌 콘텐츠와 같이 병합할 수 없는 바이너리 파일에 특히 유용합니다.

GitLab은 두 가지 유형의 파일 잠금을 지원합니다:

- 전용 파일 잠금: Git LFS 및 [`.gitattributes`](repository/files/git_attributes.md)을 사용하여 명령줄을 통해 적용됩니다. 이러한 잠금은 모든 브랜치에서 잠긴 파일 수정을 방지합니다. Free, Premium 및 Ultimate 티어에서 사용 가능합니다. 자세한 내용은 [전용 파일 잠금](../../topics/git/file_management.md#exclusive-file-locks)을 참조하세요.
- 기본 브랜치 파일 및 디렉토리 잠금: GitLab UI를 통해 적용됩니다. 이러한 잠금은 기본 브랜치에서만 파일 및 디렉토리 수정을 방지합니다.

## 기본 브랜치 파일 및 디렉토리 잠금 {#default-branch-file-and-directory-locks}

{{< details >}}

- 티어: Premium, Ultimate
- 제공 서비스: GitLab.com, GitLab Self-Managed, GitLab Dedicated

{{< /details >}}

기본 브랜치 잠금은 프로젝트 설정에서 설정한 [기본 브랜치](repository/branches/default.md)에만 적용됩니다. 이러한 잠금은 다른 브랜치의 협력자 워크플로우를 차단하지 않으면서 기본 브랜치의 안정성을 유지하는 데 도움이 됩니다.

사용자가 파일이나 디렉토리를 잠금하면:

- 잠금을 생성한 사용자만 기본 브랜치에서 파일 또는 디렉토리를 수정할 수 있습니다.
- 다른 사용자의 경우 잠긴 파일이나 디렉토리는 기본 브랜치에서 읽기 전용입니다.
- 기본 브랜치의 잠긴 파일 또는 디렉토리에 대한 직접 변경은 차단됩니다.
- 잠긴 파일 또는 디렉토리를 수정하는 머지 리퀘스트는 기본 브랜치로 병합될 수 없습니다.

> [!note]
> 기본이 아닌 브랜치에서는 모든 사용자가 여전히 잠긴 파일과 디렉토리를 수정할 수 있습니다. **잠금** 상태는 이러한 파일과 디렉토리에서 볼 수 있습니다. 이를 통해 팀 멤버는 다른 브랜치의 워크플로우를 제한하지 않으면서 진행 중인 작업을 인식할 수 있습니다.
>
> 파일 잠금은 포크 동기화 중에도 무시됩니다. 업스트림 프로젝트에서 [포크를 업데이트](repository/forking_workflow.md#update-your-fork)하면 포크의 잠긴 파일을 업스트림 프로젝트의 변경 사항으로 덮어쓸 수 있습니다.

### 권한 {#permissions}

기본 브랜치 잠금을 생성, 보기 또는 관리하려면 프로젝트의 Developer, Maintainer 또는 Owner 역할이 있어야 합니다. 자세한 내용은 [역할 및 권한](../permissions.md)을 참조하세요.

### 파일 또는 디렉토리 잠금 {#lock-a-file-or-directory}

{{< history >}}

- GitLab 17.10에서 `blob_overflow_menu`라는 [기능 플래그](../../administration/feature_flags/_index.md)로 [도입](https://gitlab.com/gitlab-org/gitlab/-/issues/519325)되었습니다. 기본적으로 비활성화되었습니다.
- GitLab 18.1에서 [일반적으로 사용 가능](https://gitlab.com/gitlab-org/gitlab/-/issues/522993)합니다. 기능 플래그 `blob_overflow_menu`이 제거되었습니다.
- 잠금 버튼이 GitLab 19.4에서 [변경](https://gitlab.com/gitlab-org/gitlab/-/issues/545279)되었으며 [기능 플래그](../../administration/feature_flags/_index.md) `repository_lock_information`를 사용합니다. 기본적으로 활성화됩니다.

{{< /history >}}

> [!flag]
> 이 기능의 사용 가능성은 기능 플래그로 제어합니다. 자세한 내용은 기록을 참조하세요.

파일 또는 디렉토리를 잠금하려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 잠금하려는 파일 또는 디렉토리로 이동합니다.
1. 오른쪽 상단 모서리에서 **잠금**을 선택합니다.
1. 확인 대화에서 **잠금**을 선택합니다.

버튼이 **잠김**으로 변경됩니다. 파일 또는 디렉토리를 잠금한 사람과 시기를 보려면 **잠김**을 선택합니다.

디렉토리 내의 파일 또는 디렉토리가 이미 잠겨 있으면 디렉토리를 잠금할 수 없습니다. 상위 디렉토리가 잠겨 있으면 디렉토리의 잠금을 해제할 수 없습니다. 두 경우 모두 버튼에 **잠김**이 표시되며 세부 정보에는 관련 잠금이 설명됩니다. 잠긴 파일 또는 디렉토리를 보려면 **잠금 보기**를 선택합니다.

**잠금**이 표시되지 않으면 파일 또는 디렉토리를 잠금할 수 있는 필수 권한이 없습니다.

### 잠긴 파일 보기 {#view-locked-files}

잠긴 파일을 보려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **코드** > **잠긴 파일**을 선택합니다.

**잠긴 파일** 페이지에는 Git LFS 전용 잠금 또는 GitLab UI로 잠긴 모든 파일이 표시됩니다.

### 파일 잠금 제거 {#remove-file-locks}

전제 조건:

- 다음 중 하나를 수행해야 합니다:
  - 잠금을 생성한 사용자여야 합니다.
  - 프로젝트의 Maintainer 또는 Owner 역할이 있어야 합니다.

잠금을 제거하려면:

{{< tabs >}}

{{< tab title="파일 또는 디렉토리에서" >}}

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 잠금 해제하려는 파일 또는 디렉토리로 이동합니다.
1. **잠김**을 선택합니다.
1. **파일 잠금 해제** 또는 **디렉토리 잠금해제**를 선택합니다.
1. 확인 대화에서 **잠금 해제**를 선택합니다.

{{< /tab >}}

{{< tab title="잠긴 파일 페이지에서" >}}

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **코드** > **잠긴 파일**을 선택합니다.
1. 잠금 해제하려는 파일의 오른쪽에서 **잠금 해제**를 선택합니다.
1. 확인 대화 상자에서 **확인**을 선택합니다.

{{< /tab >}}

{{< /tabs >}}

전용 파일 잠금을 제거하려면 [파일 잠금 및 잠금 해제](../../topics/git/file_management.md#lock-and-unlock-files)를 참조하세요.

## 머지 리퀘스트 확인 및 잠금 소유권 {#merge-request-checks-and-lock-ownership}

잠긴 파일 또는 디렉토리에 대한 변경 사항을 포함하는 머지 리퀘스트가 병합되도록 설정되면 GitLab은 머지 리퀘스트 작성자가 잠금 소유자인지 확인합니다. GitLab은 개별 커밋 작성자를 확인하지 않습니다.

예를 들어:

- 머지 리퀘스트 작성자가 파일 또는 디렉토리를 잠금한 사용자와 같으면 머지 리퀘스트를 병합할 수 있습니다.
- 머지 리퀘스트 작성자가 잠금 소유자와 다르면 머지 리퀘스트가 차단됩니다.

> [!note]
> 머지 리퀘스트 작성자가 아닌 사용자는 잠긴 파일 또는 디렉토리를 업데이트하거나 변경하는 변경 사항을 머지 리퀘스트 브랜치에 푸시할 수 있습니다. 잠금 확인은 머지 리퀘스트 작성자만 고려하므로 머지 리퀘스트는 차단되지 않습니다.

잠긴 파일에 대한 무단 변경을 방지하려면:

- 병합 전 검토가 필요한 [머지 리퀘스트 승인 규칙](merge_requests/approvals/rules.md)을 사용합니다.
- 잠긴 파일에 대한 머지 리퀘스트를 모니터링하여 승인된 변경 사항만 포함되도록 합니다.
- 워크플로우에서 기존 머지 리퀘스트 브랜치에 푸시할 수 있는 권한이 있는 사용자를 고려합니다.
