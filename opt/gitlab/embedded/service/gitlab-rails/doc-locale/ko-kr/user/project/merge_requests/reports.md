머지 리퀘스트의 **리포트** 탭에는 CI/CD 파이프라인 스캔의 상세한 검출 결과가 표시됩니다. 탭에는 보안 스캐닝 검출 결과, 라이센스 준수 결과 및 코드 품질 보고서가 전용 전체 페이지 뷰로 표시됩니다.

## 보안 스캐닝 보고서 {#security-scan-report}

{{< details >}}

- 티어: Ultimate

{{< /details >}}

보안 스캐닝 보고서는 소스 브랜치가 병합된 경우 검출 결과에서 발생할 변경 사항의 요약을 제공합니다.

예를 들어, 다음 스캔 결과가 있는 두 파이프라인을 고려합니다:

- 대상 브랜치 파이프라인이 `V1`과 `V2`로 식별된 두 취약점을 감지합니다.
- 소스 브랜치 파이프라인이 `V1`과 `V3`로 식별된 두 취약점을 감지합니다.

보안 스캐닝 보고서는 다음 결과를 표시합니다:

- `V1`은 두 브랜치에 모두 존재하므로 보고서에 표시되지 않습니다.
- `V2`은 보고서에 **수정됨**으로 표시됩니다.
- `V3`은 보고서에 **추가됨**으로 표시됩니다.

보안 스캐닝 보고서가 소스 브랜치와 대상 브랜치 간의 차이를 표시하려면 두 브랜치 모두에서 보안 보고서가 있어야 합니다. 시스템은 대상 브랜치의 10개 가장 최근 커밋에서 유효한 보안 파이프라인을 확인합니다. 각 커밋에 대해 최대 10개의 가장 최근 파이프라인에서 보안 보고서를 확인합니다.

이 방식을 사용하면 커밋이 파이프라인을 건너뛰어도 이전 커밋의 유효한 보안 보고서를 찾을 수 있습니다. 보안 보고서를 찾을 수 없으면 모든 검출 결과가 새로운 것으로 나열됩니다. 머지 리퀘스트에서 보안 스캐닝을 활성화하기 전에 기본 브랜치에서 보안 스캐닝이 활성화되었는지 확인합니다.

각 보안 보고서 유형에 대해 보고서는 심각도별로 정렬된 처음 25개의 추가된 검출 결과와 25개의 수정된 검출 결과를 표시합니다. 머지 리퀘스트의 소스 브랜치에서 모든 검출 결과를 확인하려면 **파이프라인 검출 결과 모두 보기**를 선택합니다.

### 보안 스캐닝 검출 결과 보기 {#view-security-scan-findings}

사전 요구 사항:

- 프로젝트의 개발자 역할 이상이 필요합니다.
- 프로젝트에 [보안 스캐닝을 구성](../../application_security/detect/security_configuration.md)해야 합니다.
- 보안 스캐닝이 실행되었고 머지 리퀘스트의 소스 브랜치에 대한 최신 파이프라인에서 보고서를 생성해야 합니다.

보안 스캐닝 검출 결과를 보려면:

1. 왼쪽 사이드바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. **코드** > **머지 리퀘스트**를 선택합니다.
1. 머지 리퀘스트를 선택합니다.
1. **리포트** 탭을 선택합니다.
1. **보안 스캐닝**을 선택합니다.

## 라이센스 준수 보고서 {#license-compliance-report}

{{< details >}}

- 티어: Ultimate

{{< /details >}}

라이센스 준수 보고서는 소스 브랜치 파이프라인 결과를 대상 브랜치 파이프라인 결과와 비교하여 프로젝트의 종속성에서 감지된 라이센스를 표시합니다.

라이센스는 세 가지 범주로 분류됩니다:

- **새로운 라이센스**: 소스 브랜치에서 감지되었지만 대상 브랜치에는 없는 라이센스입니다.
- **기존 라이센스**: 두 브랜치에 모두 존재하는 라이센스입니다.
- **제거된 라이센스**: 대상 브랜치에는 존재하지만 소스 브랜치에는 없는 라이센스입니다.

각 라이센스에 대해 보고서는 다음 정보를 표시합니다:

- 라이센스 이름 및 분류(허용됨, 거부됨 또는 알 수 없음)
- 라이센스를 사용하는 종속성의 수
- 패키지 관리자 및 버전 정보가 포함된 영향받는 종속성의 목록

라이센스 분류는 프로젝트의 [라이센스 승인 정책](../../compliance/license_approval_policies.md)에 의해 결정됩니다.

### 라이센스 준수 검출 결과 보기 {#view-license-compliance-findings}

사전 요구 사항:

- 프로젝트의 개발자 역할 이상이 필요합니다.
- 프로젝트에 [라이센스 스캐닝](../../compliance/license_scanning_of_cyclonedx_files/_index.md)이 구성되어 있어야 합니다.

라이센스 준수 검출 결과를 보려면:

1. 왼쪽 사이드바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. **코드** > **머지 리퀘스트**를 선택합니다.
1. 머지 리퀘스트를 선택합니다.
1. **리포트** 탭을 선택합니다.
1. **라이센스 준수**를 선택합니다.

## 코드 품질 보고서 {#code-quality-report}

코드 품질 보고서는 소스 브랜치 파이프라인 결과를 대상 브랜치 파이프라인 결과와 비교하여 머지 리퀘스트에서 감지된 코드 품질 위반을 표시합니다. 대상 브랜치의 보고서를 비교용으로 사용할 수 있으면 보고서를 사용할 수 있습니다.

보고서는 다음을 표시합니다:

- **새로운 위반**: 소스 브랜치에서 감지되었지만 대상 브랜치에는 없는 코드 품질 위반입니다.
- **해결된 위반**: 대상 브랜치에는 존재하지만 소스 브랜치에는 없는 코드 품질 위반입니다. 해결된 위반은 배지로 표시됩니다.

각 위반은 다음 정보를 표시합니다:

- 코드 품질 문제의 설명
- 심각도 수준(차단, 긴급, 주요, 경미 또는 정보)
- 위반이 발생한 파일 경로 및 줄 번호
- 확인 이름(위반을 감지한 규칙 또는 린터)

동일한 지문을 가진 중복된 위반이 제거됩니다. 단 하나의 항목만 표시됩니다.

### 코드 품질 검출 결과 보기 {#view-code-quality-findings}

사전 요구 사항:

- 개발자, 유지 관리자 또는 소유자 역할
- 프로젝트에 [코드 품질 스캐닝](../../../ci/testing/code_quality.md)이 구성되어 있음

코드 품질 검출 결과를 보려면:

1. 왼쪽 사이드바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. **코드** > **머지 리퀘스트**를 선택합니다.
1. 머지 리퀘스트를 선택합니다.
1. **리포트** 탭을 선택합니다.
1. **코드 품질**을 선택합니다.

## 문제 해결 {#troubleshooting}

보고서를 볼 때 다음 문제가 발생할 수 있습니다.

### 거부된 취약점이 보안 스캐닝 보고서에 표시됨 {#dismissed-vulnerabilities-are-visible-in-the-security-scan-report}

머지 리퀘스트에서 보안 스캐닝 보고서를 볼 때 보고서에 이미 거부된 취약점이 포함될 수 있습니다.

이 문제에 대해 사용 가능한 해결 방법이 없습니다. 제안된 해결 방법을 추적하려면 [이슈 411235](https://gitlab.com/gitlab-org/gitlab/-/issues/411235)를 참조하세요.

### 라이센스 준수 보고서가 로드 중 상태에서 멈춤 {#the-license-compliance-report-is-stuck-in-a-loading-state}

로드 스피너는 다음 시나리오에서 표시됩니다:

- 파이프라인이 진행 중일 때입니다.
- 파이프라인이 완료되었지만 여전히 백그라운드에서 결과를 구문 분석 중일 때입니다.
- 라이센스 스캐닝 작업이 완료되었지만 파이프라인이 여전히 실행 중일 때입니다.

라이센스 준수 보고서는 몇 초마다 업데이트된 결과를 폴링합니다. 파이프라인이 완료되면 파이프라인 완료 후 첫 번째 폴링이 결과 구문 분석을 트리거합니다. 생성된 보고서의 크기에 따라 몇 초가 걸릴 수 있습니다.

최종 상태는 완료되고 구문 분석되었으며 보고서에 표시된 성공적인 파이프라인 실행입니다.
