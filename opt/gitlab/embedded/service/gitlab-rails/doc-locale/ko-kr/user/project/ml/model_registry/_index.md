머신 러닝 모델 레지스트리는 머신 러닝 모델의 생명주기 전반에서 관리하기 위한 중앙 집중식 저장소 역할을 합니다. 성능 메트릭, 검증 결과, 데이터 계보 정보를 포함한 필수 메타데이터와 함께 모델 버전을 저장하는 특수 데이터베이스처럼 작동합니다.

GitLab 모델 레지스트리를 사용하여:

- 머신 러닝 모델을 체계적으로 등록하고 버전 관리
- 성능 메트릭, 매개변수, 데이터 계보를 포함한 포괄적인 메타데이터 추적
- 모델 버전을 비교하고 시간에 따른 진화 모니터링
- 모델 동작 및 요구사항에 대한 명확한 문서 유지

모델 레지스트리 기능 및 capabilities에 대한 자세한 내용은 [에픽 9423](https://gitlab.com/groups/gitlab-org/-/work_items/9423)을 참조하세요.

## 모델 레지스트리 액세스 {#access-the-model-registry}

모델 레지스트리는 패키지 레지스트리 설정으로 제어됩니다. 모델 레지스트리를 사용하기 전에 [패키지 레지스트리가 활성화되어 있는지](../../../../administration/packages/_index.md#enable-or-disable-the-package-registry) 확인하세요.

모델 레지스트리에 액세스하려면 왼쪽 사이드바에서 **배포** > **모델 레지스트리**를 선택하세요.

**모델 레지스트리**를 사용할 수 없으면 활성화되었는지 확인하세요.

모델 레지스트리를 활성화하거나 [가시성 수준](../../../public_access.md)을 공개 또는 비공개로 설정하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 그룹을 찾습니다.
1. 왼쪽 사이드바에서 **설정** > **일반**을 선택합니다.
1. **표시 여부, 프로젝트 기능, 권한**을 확장합니다.
1. **모델 레지스트리**에서 토글이 켜져 있는지 확인하고 액세스 권한을 가질 사용자를 선택하세요. 사용자는 모델 및 모델 버전을 수정하거나 삭제하려면 최소한 [보고자 역할](../../../permissions.md#roles)이 필요합니다.

## UI를 사용하여 머신 러닝 모델 생성 {#create-machine-learning-models-by-using-the-ui}

GitLab UI를 사용하여 새 머신 러닝 모델을 생성하려면:

1. 왼쪽 사이드바에서 **배포** > **모델 레지스트리**를 선택하세요.
1. **모델 레지스트리** 페이지에서 다음 중 하나를 할 수 있습니다:
   - 아직 모델이 없으면 **모델 생성**을 선택하세요.
   - 오른쪽 위 모서리에서 **모델 생성/가져오기**를 선택한 다음 드롭다운 목록에서 **새 모델 생성**을 선택하세요.
1. 필드를 완성합니다:
   - 모델의 고유한 이름을 입력하세요.
   - 선택 사항. 모델에 대한 설명을 제공하세요.
1. **생성**를 선택합니다.

모델 레지스트리에서 새로 생성된 모델을 볼 수 있습니다.

## UI를 사용하여 모델 버전 생성 {#create-a-model-version-by-using-the-ui}

새 모델 버전을 생성하려면:

1. 모델 상세 페이지에서 **새 버전 만들기**를 선택하세요.
1. 필드를 완성합니다:
   - 시멘틱 버전 관리를 따르는 고유한 버전 번호를 입력하세요.
   - 선택 사항. 모델 버전에 대한 설명을 제공하세요.
   - 모델 버전과 관련된 파일, 로그, 메트릭 또는 매개변수를 업로드하세요.
1. **만들기 및 가져오기**를 선택하세요.

새 모델 버전은 이제 모델 레지스트리에서 사용할 수 있습니다.

### 모델 삭제 {#delete-a-model}

모델 및 모든 관련 버전을 삭제하려면:

1. 왼쪽 사이드바에서 **배포** > **모델 레지스트리**를 선택하세요.
1. 삭제하려는 모델을 찾으세요.
1. 맨 오른쪽 열에서 세로 줄임표({{< icon name="ellipsis_v" >}})를 선택한 다음 **모델 삭제**를 선택하세요.

또는 모델 상세 페이지에서 모델을 삭제할 수 있습니다:

1. 왼쪽 사이드바에서 **배포** > **모델 레지스트리**를 선택하세요.
1. 삭제하려는 모델을 찾으세요.
1. 모델 이름을 선택하여 상세 정보를 확인하세요.
1. 세로 줄임표({{< icon name="ellipsis_v" >}})를 선택한 다음 **모델 삭제**를 선택하세요.
1. 삭제를 확인합니다.

### 모델 버전 삭제 {#delete-a-model-version}

모델 버전을 삭제하려면:

1. 왼쪽 사이드바에서 **배포** > **모델 레지스트리**를 선택하세요.
1. 삭제하려는 버전이 있는 모델을 찾으세요.
1. 모델 이름을 선택하여 상세 정보를 확인하세요.
1. **버전** 탭을 선택하세요.
1. 삭제하려는 모델 버전을 찾으세요.
1. 맨 오른쪽 열에서 세로 줄임표({{< icon name="ellipsis_v" >}})를 선택한 다음 **버전 삭제**를 선택하세요.

또는 모델 버전 상세 페이지에서 모델을 삭제할 수 있습니다:

1. 왼쪽 사이드바에서 **배포** > **모델 레지스트리**를 선택하세요.
1. 삭제하려는 버전이 있는 모델을 찾으세요.
1. 모델 이름을 선택하여 상세 정보를 확인하세요.
1. **버전** 탭을 선택하세요.
1. 버전 이름을 선택하여 상세 정보를 확인하세요.
1. 세로 줄임표({{< icon name="ellipsis_v" >}})를 선택한 다음 **버전 삭제**를 선택하세요.
1. 삭제를 확인합니다.

### 모델 버전에 아티팩트 추가 {#add-artifacts-to-a-model-version}

모델 버전에 아티팩트를 추가하려면:

1. 왼쪽 사이드바에서 **배포** > **모델 레지스트리**를 선택하세요.
1. 모델을 찾으세요.
1. 모델 이름을 선택하여 상세 정보를 확인하세요.
1. **버전** 탭을 선택하세요.
1. 버전 이름을 선택하여 상세 정보를 확인하세요.
1. **아티팩트** 탭을 선택하세요.
1. 선택 사항. 업로드할 파일의 서브폴더 경로를 지정하세요. 예: `config`.
1. **선택**을 사용하여 업로드할 파일을 선택하세요.
1. **업로드**를 선택하세요.

또는 드롭 영역에 파일을 끌어다놓을 수 있습니다. 아티팩트는 자동으로 업로드됩니다.

각 파일의 크기 제한이 5GB이므로 더 큰 모델을 분할해야 합니다.

### 모델 버전에서 아티팩트 삭제 {#delete-artifacts-from-a-model-version}

버전에서 아티팩트를 삭제하려면:

1. 왼쪽 사이드바에서 **배포** > **모델 레지스트리**를 선택하세요.
1. 모델을 찾으세요.
1. 모델 이름을 선택하여 상세 정보를 확인하세요.
1. **버전** 탭을 선택하세요.
1. 버전 이름을 선택하여 상세 정보를 확인하세요.
1. **아티팩트** 탭을 선택하세요.
1. 삭제하려는 각 아티팩트 옆의 상자를 선택하세요.
1. **삭제**를 선택합니다.
1. 삭제를 확인합니다.

## MLflow를 사용하여 머신 러닝 모델 및 모델 버전 생성 {#create-machine-learning-models-and-model-versions-by-using-mlflow}

모델 및 모델 버전은 [MLflow](https://www.mlflow.org/docs/latest/tracking.html) 클라이언트 호환성을 사용하여 생성할 수 있습니다. 모델 및 모델 버전을 생성하고 관리하는 방법에 대한 자세한 내용은 [MLflow 클라이언트 호환성](../experiment_tracking/mlflow_client.md#model-registry)을 참조하세요. 모델 레지스트리 페이지에서 **모델 생성**을 선택하여 GitLab에서 직접 모델을 생성할 수도 있습니다.

### MLflow를 사용하여 모델 버전에 아티팩트, 메트릭 및 매개변수 추가 {#add-artifacts-metrics-and-parameters-to-a-model-version-by-using-mlflow}

파일은 다음을 사용하여 모델 버전에 업로드할 수 있습니다:

- 패키지 레지스트리. 여기서 모델 버전은 `<model_name>/<model_version>` 이름의 패키지와 연결됩니다.
- MLflow 클라이언트 호환성. [세부 정보 보기](../experiment_tracking/mlflow_client.md#logging-artifacts-to-a-model-version).

사용자는 MLflow 클라이언트 호환성을 통해 모델 버전의 메트릭 및 매개변수를 기록할 수 있습니다. [세부 정보 확인](../experiment_tracking/mlflow_client.md#logging-metrics-and-parameters-to-a-model-version).

## 모델 버전을 CI/CD 작업에 연결 {#link-a-model-version-to-a-cicd-job}

GitLab CI/CD 작업을 통해 모델 버전을 생성할 때 모델 버전을 작업에 연결하여 작업의 로그, 병합 요청 및 파이프라인에 편리하게 액세스할 수 있습니다. 이는 MLflow 클라이언트 호환성을 통해 수행할 수 있습니다. [세부 정보 보기](../experiment_tracking/mlflow_client.md#linking-a-model-version-to-a-cicd-job).

## 모델 버전 및 시멘틱 버전 관리 {#model-versions-and-semantic-versioning}

GitLab의 모델 버전 버전은 [시멘틱 버전 사양](https://semver.org/)을 따라야 합니다. 시멘틱 버전 관리를 사용하면 새 버전을 애플리케이션에 변경 없이 배포할 수 있는지 여부를 전달하여 모델 배포를 용이하게 합니다:

- **주요 버전(정수)**: 주요 구성요소의 변경은 모델의 호환성을 깨뜨리는 변경을 의미하며, 모델을 사용하는 애플리케이션을 이 새 버전을 올바르게 사용하도록 업데이트해야 합니다. 새로운 알고리즘이나 필수 기능 열 추가는 주요 구성요소에서 버전을 올려야 하는 호환성 깨지는 변경의 예입니다.

- **부 버전(정수)**: 부 구성요소의 변경은 호환성을 깨뜨리지 않는 변경을 의미하며, 소비자는 호환성을 깨뜨리지 않고 새 버전을 안전하게 사용할 수 있습니다. 다만 소비자는 새로운 기능을 사용하도록 업데이트해야 할 수 있습니다. 예를 들어 기본값이 있는 필수가 아닌 기능 열을 모델에 추가하는 것은 부 버전을 올리는 것입니다. 추가된 열에 대한 값이 전달되지 않으면 추론이 여전히 작동하기 때문입니다.

- **패치 버전(정수)**: 패치 구성요소의 변경은 애플리케이션에서 어떤 조치도 필요 없는 새 버전이 출시되었음을 의미합니다. 예를 들어 모델의 일일 재교육은 기능 집합을 변경하거나 애플리케이션이 모델 버전을 사용하는 방식을 변경하지 않습니다. 새 패치로 자동 업데이트하는 것은 안전한 업데이트입니다.

- **사전 릴리스(텍스트)**: 프로덕션 사용에 아직 준비되지 않은 버전을 나타냅니다. 모델의 알파, 베타 또는 릴리스 후보 버전을 식별하는 데 사용됩니다.

### 모델 버전 예 {#model-version-examples}

- 초기 릴리스: 1.0.0 - 모델의 첫 릴리스로 변경 사항이나 패치가 없습니다.
- 새로운 기능: 1.1.0 - 모델에 새로운 호환성을 깨뜨리지 않는 기능이 추가되어 부 버전이 증가합니다.
- 버그 수정: 1.1.1 - 모델의 버그가 수정되어 패치 버전이 증가합니다.
- 호환성 깨지는 변경: 2.0.0 - 모델에 호환성을 깨뜨리는 변경이 적용되어 주요 버전이 증가합니다.
- 패치 릴리스: 2.0.1 - 모델의 버그가 수정되어 패치 버전이 증가합니다.
- 사전 릴리스: 2.0.1-alpha1 - 알파 릴리스인 모델의 사전 릴리스 버전입니다.
- 사전 릴리스: 2.0.1-rc2 - 모델의 릴리스 후보 버전입니다.
- 새로운 기능: 2.1.0 - 모델에 새로운 기능이 추가되어 부 버전이 증가합니다.
