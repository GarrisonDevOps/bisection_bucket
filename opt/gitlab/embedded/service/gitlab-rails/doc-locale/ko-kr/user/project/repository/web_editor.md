웹 편집기는 로컬 설정 없이 GitLab 리포지토리에 변경 사항을 적용할 수 있는 브라우저 기반 도구입니다. 다음과 같이 수행할 수 있습니다.

- 단일 파일을 편집하고 변경 사항을 커밋하기 전에 미리 봅니다.
- 새 파일 및 디렉토리를 생성합니다.
- 파일을 업로드하고 대체합니다.
- 버전 제어를 위해 브랜치 및 태그를 생성합니다.
- [파일 잠금](../file_lock.md#lock-a-file-or-directory)을 사용하여 동시 편집 충돌을 방지합니다.
- Git을 로컬에서 설정하지 않고 프로젝트에 기여합니다.

GitLab은 웹 편집기 커밋에 [기본 이메일 주소](../../profile/_index.md#change-the-email-displayed-on-your-commits)를 사용합니다.

여러 파일에 대한 변경 사항의 경우 [웹 IDE](../web_ide/_index.md)를 사용합니다.

> [!note]
> [보호된 브랜치](branches/protected.md)에서 파일을 관리하려면 적절한 [권한](../../permissions.md)이 필요합니다.

## 파일 관리 {#manage-files}

웹 편집기를 사용하여 GitLab UI에서 직접 파일을 생성, 편집, 업로드 및 삭제할 수 있습니다.

### 파일 생성 {#create-a-file}

웹 편집기에서 텍스트 파일을 생성하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 새 파일을 생성할 디렉토리로 이동합니다.
1. 디렉토리 이름 옆에서 더하기 아이콘({{< icon name="plus" >}}) > **새 파일**을 선택합니다.
1. 브랜치 이름 옆에 파일명 및 확장자를 입력합니다. 예를 들어, `my_file.md`입니다.
1. 파일에 내용을 추가합니다.
1. **변경 사항 커밋**을 선택합니다.
1. **커밋 메시지** 필드에 커밋 이유를 입력합니다.
1. 다음 옵션 중 하나를 선택합니다.

   - 파일을 미리 채워진 대상 브랜치에 생성하려면 **변경 사항 커밋**을 선택합니다.
   - 새 브랜치에서 파일을 생성하고 변경 사항을 커밋하려면:

     1. **새 브랜치로 커밋**을 선택합니다.
     1. 브랜치 이름을 입력합니다.
     1. **이 변경 사항에 대한 병합 요청을 만듭니다.** 체크박스가 선택 해제되어 있는지 확인합니다.
     1. **변경 사항 커밋**을 선택합니다.

   - 새 브랜치에서 파일을 생성하고 변경 사항을 커밋한 후 병합 요청을 생성하려면:

     1. **새 브랜치로 커밋**을 선택합니다.
     1. 브랜치 이름을 입력합니다.
     1. **이 변경 사항에 대한 병합 요청을 만듭니다.** 체크박스가 선택되어 있는지 확인합니다.
     1. **변경 사항 커밋**을 선택합니다.

미리 채워진 콘텐츠로 새 파일 편집기를 열려면 URL에서 `content` 쿼리 매개 변수를 사용합니다. 예를 들어:

```plaintext
https://gitlab.com/<your-namespace>/<your-project>/-/new/main?content=your+content+here
```

#### 템플릿으로부터 {#from-a-template}

웹 편집기의 템플릿에서 텍스트 파일을 생성하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 새 파일을 생성할 디렉토리로 이동합니다.
1. 디렉토리 이름 옆에서 더하기 아이콘({{< icon name="plus" >}}) > **새 파일**을 선택합니다.
1. **파일명**에 GitLab이 템플릿을 제공하는 이름을 입력합니다:
   - `.gitignore`
   - `.gitlab-ci.yml`
   - `LICENSE`
   - `Dockerfile`
1. **템플릿 적용** 드롭다운 목록에서 템플릿을 선택합니다.
1. 선택 사항. 필요에 따라 템플릿을 업데이트합니다.
1. [파일 생성](#create-a-file) 프로세스의 6단계부터 계속합니다.

### 파일 편집 {#edit-a-file}

웹 편집기에서 텍스트 파일을 편집하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 편집하려는 파일로 이동합니다.
1. **편집** > **단일 파일 편집**을 선택합니다.
1. 변경 사항을 만듭니다.
1. **변경 사항 커밋**을 선택합니다.
1. **커밋 메시지** 필드에 커밋 이유를 입력합니다.
1. 다음 옵션 중 하나를 선택합니다.

   - 파일을 미리 채워진 대상 브랜치에서 편집하려면 **변경 사항 커밋**을 선택합니다.
   - 새 브랜치에서 파일을 편집하고 변경 사항을 커밋하려면:

     1. **새 브랜치로 커밋**을 선택합니다.
     1. 브랜치 이름을 입력합니다.
     1. **이 변경 사항에 대한 병합 요청을 만듭니다.** 체크박스가 선택 해제되어 있는지 확인합니다.
     1. **변경 사항 커밋**을 선택합니다.

   - 새 브랜치에서 파일을 편집하고 변경 사항을 커밋한 후 병합 요청을 생성하려면:

     1. **새 브랜치로 커밋**을 선택합니다.
     1. 브랜치 이름을 입력합니다.
     1. **이 변경 사항에 대한 병합 요청을 만듭니다.** 체크박스가 선택되어 있는지 확인합니다.
     1. **변경 사항 커밋**을 선택합니다.
     1. 필드를 작성하고 **병합 요청 생성**를 선택합니다.

> [!note]
> 편집 중인 동안 다른 사용자가 같은 파일을 편집하고 커밋하면 변경 사항을 커밋할 수 없습니다. 다음 오류 메시지가 표시됩니다. `Someone edited the file the same time you did. Please check out the file and
> make sure your change will not unintentionally remove theirs.`

#### 특정 줄로 링크 {#link-to-specific-lines}

웹 편집기에서 한 줄 또는 여러 줄로 링크하려면 URL의 파일명 세그먼트에 해시 정보를 추가합니다. 예를 들어:

- `MY_FILE.js#L3`은(는) `MY_FILE.js`에서 3번 줄을 강조합니다.
- `MY_FILE.js#L3-10`은(는) `MY_FILE.js`에서 3~10번 줄을 강조합니다.

파일을 편집할 때 줄 번호를 선택하여 한 줄로 링크할 수도 있습니다.

#### 포크된 병합 요청에서 파일 편집 {#edit-files-in-a-forked-merge-request}

사전 요구 사항:

- 포크에서 병합 요청으로 작업해야 합니다.
- [업스트림 멤버의 커밋 허용](../merge_requests/allow_collaboration.md#allow-commits-from-upstream-members)이 활성화되어야 합니다.

포크된 프로젝트의 병합 요청으로 작업 중인 경우 파일을 편집하고 변경 사항을 커밋할 수 있습니다. 다음과 같이 설정합니다.

1. 병합 요청으로 이동합니다.
1. 편집하려는 파일로 이동합니다.
1. **편집** > **단일 파일 편집**을 선택합니다.
1. **변경 사항 커밋**을 선택합니다.
1. **커밋 메시지**에 커밋 이유를 입력합니다. 다음 정보가 제공됩니다. `Your changes can be committed to <branch-name> because a merge request is open.`
1. **변경 사항 커밋**을 선택합니다.

### 파일 미리보기 {#preview-a-file}

{{< history >}}

- 새 파일의 미리보기가 GitLab 19.4에 [도입](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/253963)되었습니다.

{{< /history >}}

웹 편집기에서 파일을 생성하거나 편집할 때 커밋하기 전에 콘텐츠를 미리 볼 수 있습니다.

콘텐츠를 미리 보려면 **미리보기** 탭을 선택합니다. 표시되는 내용은 파일 확장자에 따라 달라집니다:

- 마크다운 파일은 입력하는 동안 업데이트되는 콘텐츠 옆에 라이브 미리보기를 표시합니다.
- AsciiDoc, Org 및 reStructuredText와 같은 다른 마크업 파일은 렌더링된 마크업을 표시합니다.
- 다른 모든 파일은 변경 사항의 diff를 표시합니다.

콘텐츠로 돌아가려면 **쓰기** 탭을 선택합니다.

마크업이 아닌 파일을 편집할 때 탭의 레이블은 **변경 내용 미리보기**입니다.

### 파일 변경 취소 {#cancel-file-changes}

웹 편집기에서 파일 변경 사항, 편집, 업로드 또는 삭제를 취소하려면:

1. **취소**를 선택합니다.
1. 다음 중 하나를 선택합니다.

   - 변경 사항 취소를 확인합니다: **확인**을 선택합니다.
   - 변경 사항을 취소하지 않습니다: **취소**를 선택합니다.

### 동작 메뉴의 파일 작업 {#file-operations-from-the-actions-menu}

{{< history >}}

- GitLab 17.10에서 `blob_overflow_menu`라는 [기능 플래그](../../../administration/feature_flags/_index.md)로 [도입](https://gitlab.com/gitlab-org/gitlab/-/issues/519325)되었습니다. 기본적으로 비활성화되었습니다.
- GitLab 18.1에서 [일반적으로 사용 가능](https://gitlab.com/gitlab-org/gitlab/-/issues/522993)합니다. 기능 플래그 `blob_overflow_menu`이 제거되었습니다.

{{< /history >}}

**조치**({{< icon name="ellipsis_v" >}}) 메뉴는 파일 작업을 드롭다운 목록으로 통합합니다. 이 메뉴에서 다음을 수행할 수 있습니다:

- 파일을 편집합니다.
- 파일을 업로드합니다.
- 파일을 삭제합니다.
- 파일을 대체합니다.

이러한 작업을 완료하려면:

1. GitLab에서 파일을 엽니다.
1. 오른쪽 상단 모서리의 파일명 옆에서 **조치**({{< icon name="ellipsis_v" >}})을 선택합니다.
1. 원하는 작업을 선택합니다.

## 디렉토리 생성 {#create-a-directory}

웹 편집기에서 디렉토리를 생성하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 새 디렉토리를 생성할 디렉토리로 이동합니다.
1. 디렉토리 이름 옆에서 더하기 아이콘({{< icon name="plus" >}}) > **새 디렉토리**를 선택합니다.
1. **디렉토리 이름** 필드에 디렉토리 이름을 입력합니다.
1. **커밋 메시지**에 커밋 이유를 입력합니다.
1. 다음 옵션 중 하나를 선택합니다:

   - 디렉토리를 미리 채워진 대상 브랜치에서 생성하려면 **변경 사항 커밋**을 선택합니다.
   - 새 브랜치에서 디렉토리를 생성하고 변경 사항을 커밋하려면:

     1. **새 브랜치로 커밋**을 선택합니다.
     1. 브랜치 이름을 입력합니다.
     1. **이 변경 사항에 대한 병합 요청을 만듭니다.** 체크박스가 선택 해제되어 있는지 확인합니다.
     1. **변경 사항 커밋**을 선택합니다.

   - 새 브랜치에서 디렉토리를 생성하고 변경 사항을 커밋한 후 병합 요청을 생성하려면:

     1. **새 브랜치로 커밋**을 선택합니다.
     1. 브랜치 이름을 입력합니다.
     1. **이 변경 사항에 대한 병합 요청을 만듭니다.** 체크박스가 선택되어 있는지 확인합니다.
     1. **변경 사항 커밋**을 선택합니다.

## 편집기 접근성 옵션 {#editor-accessibility-options}

웹 편집기는 [Monaco Editor](https://github.com/microsoft/monaco-editor)를 기반으로 하며 여러 [접근성 기능](https://github.com/microsoft/monaco-editor/wiki/Monaco-Editor-Accessibility-Guide)을 포함하고 있습니다:

| 기능                          | Windows 또는 Linux의 단축키      | macOS의 단축키                                    | 세부 정보 |
|----------------------------------|-----------------------------------|------------------------------------------------------|---------|
| 키보드 탐색 명령 목록 | <kbd>F1</kbd>                     | <kbd>F1</kbd>                                        | 마우스 없이 편집기를 더 쉽게 사용할 수 있도록 하는 [명령 목록](https://github.com/microsoft/monaco-editor/wiki/Monaco-Editor-Accessibility-Guide#keyboard-navigation)입니다. |
| 탭 트래핑                     | <kbd>Control</kbd>+<kbd>m</kbd> | <kbd>Control</kbd>+<kbd>Shift</kbd>+<kbd>m</kbd> | 탭 문자를 삽입하는 대신 페이지의 다음 포커스 가능한 요소로 이동하도록 [탭 트래핑](https://github.com/microsoft/monaco-editor/wiki/Monaco-Editor-Accessibility-Guide#tab-trapping)을 활성화합니다. |
