GitLab에서 대부분의 작업은 [프로젝트](_index.md)에서 수행됩니다. 파일과 코드는 프로젝트에 저장되며, 대부분의 기능은 프로젝트 범위 내에 있습니다.

## 프로젝트 개요 {#project-overview}

**프로젝트 개요** 페이지를 선택하면 프로젝트 콘텐츠가 표시됩니다:

- 리포지토리의 파일
- 프로젝트 정보(설명)
- 주제
- 배지
- 프로젝트의 별, 포크, 커밋, 브랜치, 태그, 릴리스 및 환경의 개수
  - 커밋 개수는 프로젝트의 기본 브랜치에서 계산되며, 모든 브랜치에서는 계산되지 않습니다.
- 프로젝트 저장소 크기
- 선택적 파일 및 구성
- `README` 또는 인덱스 파일
  - 위키 페이지
  - 라이선스
  - 변경 로그
  - 기여 지침
  - Kubernetes 클러스터
  - CI/CD 구성
  - 통합
  - GitLab Pages
- 생성 날짜

공개 프로젝트 및 [프로젝트 코드를 볼 수 있는 권한](../permissions.md#project-permissions)이 있는 내부 및 비공개 프로젝트의 멤버인 경우 프로젝트 개요 페이지에 다음이 표시됩니다:

- [`README` 또는 인덱스 파일](repository/files/_index.md#readme-and-index-files).
- 프로젝트 리포지토리의 디렉터리 목록입니다.

프로젝트 코드를 볼 수 있는 권한이 없는 사용자의 경우 개요 페이지에 다음이 표시됩니다:

- 위키 홈페이지입니다.
- 프로젝트의 이슈 목록입니다.

`https://gitlab.example.com/projects/<id>`을 사용하여 프로젝트 이름 대신 해당 ID로 프로젝트에 액세스할 수 있습니다. 예를 들어, 개인 네임스페이스 `alex`에 ID `123456`인 프로젝트 `my-project`가 있는 경우 `https://gitlab.example.com/alex/my-project` 또는 `https://gitlab.example.com/projects/123456`에서 프로젝트에 액세스할 수 있습니다.

> [!note]
> GitLab 17.5 이상에서는 이 엔드포인트에 `https://gitlab.example.com/-/p/<id>`를 사용할 수도 있습니다.

## 프로젝트 ID 찾기 {#find-the-project-id}

[GitLab API](../../api/_index.md)를 사용하여 프로젝트와 상호 작용하려면 프로젝트 ID가 필요할 수 있습니다.

프로젝트 ID를 찾으려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 프로젝트 개요 페이지의 오른쪽 위 모서리에서 **조치**({{< icon name="ellipsis_v" >}})을 선택합니다.
1. **프로젝트 ID 복사**를 선택합니다.

## 프로젝트 보기 {#view-projects}

**프로젝트** 목록을 사용하여 다음을 봅니다:

- 인스턴스의 모든 프로젝트
- 작업하거나 소유한 프로젝트
- 보관된 프로젝트 및 삭제 대기 중인 프로젝트를 포함한 비활성 프로젝트

### 인스턴스의 모든 프로젝트 탐색 {#explore-all-projects-on-an-instance}

{{< history >}}

- 트렌드 프로젝트 탭이 GitLab 19.0에서 [제거](https://gitlab.com/groups/gitlab-org/-/work_items/18493)되었습니다. `retire_trending_projects` 기능 플래그가 기본적으로 활성화됩니다.
- `retire_trending_projects` 기능 플래그가 GitLab 19.1에서 제거되었습니다.

{{< /history >}}

GitLab 인스턴스의 모든 프로젝트를 봅니다. 활성 및 비활성 프로젝트별로 목록을 필터링합니다:

- 활성 프로젝트는 최근 활동 또는 진행 중인 개발이 있는 프로젝트입니다.
- 비활성 프로젝트는 보관되었거나 삭제가 예약된 프로젝트입니다.

인증되지 않은 경우 목록에는 공개 프로젝트만 표시됩니다.

GitLab 인스턴스의 프로젝트를 보려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택합니다.
1. **탐색**을 선택합니다.
1. 선택 사항. 표시할 프로젝트를 필터링하는 탭을 선택합니다.

### 작업하는 프로젝트 보기 {#view-projects-you-work-with}

{{< history >}}

- GitLab 17.9에서 `your_work_projects_vue` [기능 플래그](../../administration/feature_flags/_index.md)로 [도입](https://gitlab.com/groups/gitlab-org/-/work_items/13066)되었습니다. 기본적으로 비활성화되었습니다.
- GitLab 17.9에서 **귀하**에서 **멤버**로 탭 레이블이 [변경](https://gitlab.com/groups/gitlab-org/-/work_items/13066)되었으며, [기능 플래그](../../administration/feature_flags/_index.md) `your_work_projects_vue`가 있습니다. 기본적으로 비활성화되었습니다.
- GitLab 17.10에서 [일반적으로 사용 가능](https://gitlab.com/gitlab-org/gitlab/-/issues/465889)합니다. 기능 플래그 `your_work_projects_vue`이 제거되었습니다.

{{< /history >}}

상호 작용한 프로젝트를 보려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택합니다.
1. **내 모든 프로젝트 보기**를 선택합니다.
1. 선택 사항. 표시할 프로젝트를 필터링하는 탭을 선택합니다:
   - **기여함**: 다음을 수행한 프로젝트:
     - 이슈, 병합 요청 또는 에픽 생성
     - 이슈, 병합 요청 또는 에픽에 댓글 달기
     - 이슈, 병합 요청 또는 에픽 종료
     - 커밋 푸시
     - 병합 요청 승인
     - 병합 요청 병합
   - **별점**: [별표](#star-a-project)한 프로젝트
   - **개인**: 개인 네임스페이스 아래에 생성된 프로젝트
   - **멤버**: 멤버인 프로젝트
   - **비활성**: 보관된 프로젝트 및 삭제 대기 중인 프로젝트

개인 프로필에서 별표된 프로젝트와 개인 프로젝트를 볼 수도 있습니다:

1. 오른쪽 위 모서리에서 아바타를 선택하고 사용자 이름을 선택합니다.
1. 왼쪽 사이드바에서 **별점을 받은 프로젝트** 또는 **개인 프로젝트**를 선택합니다.

### 비활성 프로젝트 보기 {#view-inactive-projects}

{{< history >}}

- GitLab 17.9에서 "삭제 대기 중"에서 "비활성"으로 탭 레이블이 [변경](https://gitlab.com/groups/gitlab-org/-/work_items/13066)되었으며, [기능 플래그](../../administration/feature_flags/_index.md) `your_work_projects_vue`가 있습니다. 기본적으로 비활성화되었습니다.
- [탭 레이블을 일반적으로 사용 가능](https://gitlab.com/gitlab-org/gitlab/-/issues/465889)하게 GitLab 17.10에서 변경했습니다. 기능 플래그 `your_work_projects_vue`이 제거되었습니다.
- GitLab Premium에서 GitLab Free로 18.0에서 [이동](https://gitlab.com/groups/gitlab-org/-/work_items/17208)되었습니다.
- GitLab 18.0에서 [개인 네임스페이스의 프로젝트에 대해 활성화](https://gitlab.com/gitlab-org/gitlab/-/issues/536244)되었습니다.

{{< /history >}}

프로젝트는 삭제 대기 중이거나 보관된 경우에 비활성입니다.

모든 비활성 프로젝트를 보려면:

1. 다음 중 하나를 선택합니다:
   - **내 모든 프로젝트 보기** \- 프로젝트를 필터링합니다.
   - **탐색** \- 액세스할 수 있는 모든 프로젝트를 필터링합니다.
1. **비활성** 탭을 선택합니다.

목록의 각 비활성 프로젝트는 프로젝트가 보관되었거나 삭제 대기 중임을 나타내는 배지를 표시합니다.

프로젝트가 삭제 대기 중인 경우 목록에는 다음도 표시됩니다:

- 프로젝트가 최종 삭제되도록 예약된 시간입니다.
- **복원** 동작입니다. 프로젝트를 복원할 때:
  - **삭제 대기 중** 레이블이 제거됩니다. 프로젝트는 더 이상 삭제가 예약되지 않습니다.
  - 프로젝트가 **비활성** 탭에서 제거됩니다.

### 소유한 프로젝트만 보기 {#view-only-projects-you-own}

소유한 프로젝트만 보려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택합니다.
1. 다음 중 하나를 선택합니다:
   - **모든 프로젝트 보기** \- 프로젝트를 필터링합니다.
   - **탐색** \- 액세스할 수 있는 모든 프로젝트를 필터링합니다.
1. 프로젝트 목록 위에서 **검색 또는 결과 필터**를 선택합니다.
1. **역할** 드롭다운 목록에서 **소유자**를 선택합니다.

## 프로젝트 활동 보기 {#view-project-activity}

프로젝트에서 수행한 최근 동작을 볼 수 있습니다:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **관리** > **활동**을 선택하세요.
1. 선택 사항. 기여 유형별로 활동을 필터링하려면 탭을 선택합니다:

   - **전체**: 프로젝트 멤버의 모든 기여입니다.
   - **푸시 이벤트**: 프로젝트의 푸시 이벤트입니다.
   - **머지 이벤트**: 프로젝트에서 수락된 병합 요청입니다.
   - **이슈 이벤트**: 프로젝트에서 열었거나 종료된 이슈입니다.
   - **댓글**: 프로젝트 멤버가 게시한 댓글입니다.
   - **디자인**: 프로젝트에서 추가, 업데이트 및 제거된 디자인입니다.
   - **팀**: 프로젝트에 참여하고 떠난 멤버입니다.

1. 선택 사항. 이 활동의 RSS 피드를 구독하려면 피드 기호({{< icon name="rss" >}})를 선택합니다.

GitLab은 성능상의 이유로 3년 이상 된 프로젝트 활동 이벤트를 이벤트 테이블에서 제거합니다.

## 언어별로 프로젝트 필터링 {#filter-projects-by-language}

프로젝트를 사용하는 프로그래밍 언어로 필터링할 수 있습니다. 다음과 같이 설정합니다.

1. 상단 표시줄에서 **검색 또는 이동**을 선택합니다.
1. 다음 중 하나를 선택합니다:
   - **모든 프로젝트 보기** \- 프로젝트를 필터링합니다.
   - **탐색** \- 액세스할 수 있는 모든 프로젝트를 필터링합니다.
1. 프로젝트 목록 위에서 **검색 또는 결과 필터**를 선택합니다.
1. **언어** 드롭다운 목록에서 프로젝트를 필터링할 언어를 선택합니다.

선택한 언어를 사용하는 프로젝트 목록이 표시됩니다.

## 프로젝트에 별 표시 {#star-a-project}

자주 사용하는 프로젝트에 별 표시를 하여 찾기 쉽게 할 수 있습니다.

프로젝트에 별 표시를 하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 페이지의 오른쪽 위 모서리에서 **별점**을 선택합니다.

## 프로젝트 나가기 {#leave-a-project}

프로젝트를 나갈 때:

- 더 이상 프로젝트 멤버가 아니며 기여할 수 없습니다.
- 자신에게 할당된 모든 이슈와 병합 요청이 할당되지 않습니다.

사전 요구 사항:

- 프로젝트가 [그룹 네임스페이스](../namespace/_index.md) 아래의 그룹의 일부인 경우에만 이 방법으로 프로젝트를 나갈 수 있습니다.
- 프로젝트의 [직접 멤버](members/_index.md#membership-types)여야 합니다.

프로젝트를 나가려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 프로젝트 개요 페이지의 오른쪽 위 모서리에서 **조치**({{< icon name="ellipsis_v" >}})을 선택합니다.
1. **프로젝트에서 나가기**를 선택한 후 **프로젝트에서 나가기**를 다시 선택합니다.

**귀하의 작업** 목록 보기에서 직접 프로젝트를 나가려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택합니다.
1. **내 모든 프로젝트 보기**를 선택합니다.
1. **멤버** 탭에서 나갈 프로젝트를 찾고 세로 줄임표({{< icon name="ellipsis_v" >}})를 선택합니다.
1. **프로젝트에서 나가기**를 선택합니다.

이 작업은 다른 목록 페이지에서도 사용할 수 있습니다.

## 프로젝트 편집 {#edit-a-project}

프로젝트 일반 설정을 사용하여 프로젝트 세부정보를 편집합니다.

사전 요구 사항:

- 프로젝트에 대해 유지 관리자 또는 소유자 역할이 있어야 합니다.

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **설정** > **일반**을 선택합니다.
1. **프로젝트 이름** 텍스트 상자에 프로젝트 이름을 입력합니다. [프로젝트 이름의 제한](../reserved_names.md)을 참조하세요.
1. 선택 사항. **프로젝트 설명** 텍스트 상자에 프로젝트 설명을 입력합니다. 설명은 2,000자로 제한됩니다. CI/CD 카탈로그에 게시된 구성 요소에는 프로젝트 설명이 필요합니다.
1. **변경 사항 저장**을 선택합니다.

### 리포지토리 이름 바꾸기 {#rename-a-repository}

프로젝트의 리포지토리 이름은 해당 URL을 정의합니다.

사전 요구 사항:

- 관리자이거나 프로젝트에 대한 유지 관리자 또는 소유자 역할이 있어야 합니다.

> [!note]
> 리포지토리 경로를 변경하면 사용자가 기존 URL에서 푸시하거나 끌어올 때 문제가 발생할 수 있습니다. 리다이렉트 기간 및 부작용에 대한 자세한 내용은 [리포지토리 이름 바꿀 때의 리다이렉트](repository/_index.md#repository-path-changes)를 참조하세요.

리포지토리 이름을 바꾸려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **설정** > **일반**을 선택합니다.
1. **고급**을 펼치세요.
1. **경로 변경** 텍스트 상자에서 경로를 편집합니다.
1. **경로 변경**을 선택합니다.

### 프로젝트 아바타 추가 {#add-a-project-avatar}

프로젝트 아바타를 추가하여 프로젝트를 시각적으로 식별하는 데 도움이 됩니다. 아바타를 추가하지 않으면 GitLab이 프로젝트 이름의 첫 번째 문자를 기본 프로젝트 아바타로 표시합니다.

프로젝트 아바타를 추가하려면 다음 방법 중 하나를 사용합니다:

- 리포지토리에 로고를 추가합니다.
- 프로젝트 설정에서 아바타를 업로드합니다.

#### 리포지토리에 로고 추가 {#add-a-logo-to-your-repository}

프로젝트 설정에 아바타를 업로드하지 않은 경우 GitLab은 리포지토리에서 `logo`이라는 파일을 찾아 기본 프로젝트 아바타로 사용합니다.

사전 요구 사항:

- 프로젝트에 대해 유지 관리자 또는 소유자 역할이 있어야 합니다.
- 파일은 200KB 이하여야 합니다. 이상적인 이미지 크기는 192 x 192 픽셀입니다.
- 파일의 이름은 `logo`이고 확장명은 `.png`, `.jpg` 또는 `.gif`여야 합니다. 예를 들어, `logo.gif`입니다.

프로젝트 아바타로 사용할 로고 파일을 추가하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 프로젝트 리포지토리의 루트에 로고 파일을 업로드합니다.

#### 프로젝트 설정에서 아바타 업로드 {#upload-an-avatar-in-project-settings}

사전 요구 사항:

- 프로젝트에 대해 유지 관리자 또는 소유자 역할이 있어야 합니다.
- 파일은 200KB 이하여야 합니다. 이상적인 이미지 크기는 192 x 192 픽셀입니다.
- 이미지는 다음 파일 유형 중 하나여야 합니다:
  - `.bmp`
  - `.gif`
  - `.ico`
  - `.jpeg`
  - `.png`
  - `.tiff`

프로젝트 설정에서 아바타를 업로드하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **설정** > **일반**을 선택합니다.
1. **프로젝트 아바타** 섹션에서 **파일 선택**을 선택합니다.
1. 아바타 파일을 선택합니다.
1. **변경 사항 저장**을 선택합니다.

## 프로젝트 삭제 {#delete-a-project}

{{< history >}}

- 기본 동작이 16.0에서 [GitLab.com](https://gitlab.com/gitlab-org/gitlab/-/issues/393622) 및 [GitLab Self-Managed](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/119606)의 Premium 및 Ultimate 티어에 대해 지연된 프로젝트 삭제로 [변경](https://gitlab.com/gitlab-org/gitlab/-/issues/389557)되었습니다.
- 기본 동작이 18.0에서 [GitLab Free](https://gitlab.com/groups/gitlab-org/-/work_items/17208) 및 [개인 프로젝트](https://gitlab.com/gitlab-org/gitlab/-/issues/536244)에 대해 지연된 프로젝트 삭제로 변경되었습니다.

{{< /history >}}

기본적으로 처음 프로젝트를 삭제하면 삭제 대기 상태가 됩니다. 프로젝트를 다시 삭제하여 즉시 제거합니다.

사전 요구 사항:

- 프로젝트에 대해 소유자 역할이 있어야 합니다.
- 소유자는 [프로젝트를 삭제할 수 있어야](../../administration/settings/visibility_and_access_controls.md#restrict-project-deletion-to-administrators) 합니다.

프로젝트를 삭제하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 프로젝트 개요 페이지의 오른쪽 위 모서리에서 **조치**({{< icon name="ellipsis_v" >}})을 선택합니다.
1. **삭제**를 선택합니다.
1. 확인 대화 상자에서 프로젝트 이름을 입력하고 **예, 프로젝트를 삭제합니다.**를 선택합니다.

이 동작은 프로젝트를 삭제로 표시하는 백그라운드 작업을 추가합니다. GitLab.com에서는 프로젝트가 30일 후에 삭제됩니다. GitLab Self-Managed에서는 [인스턴스 설정](../../administration/settings/visibility_and_access_controls.md#deletion-protection)을 통해 보유 기간을 수정할 수 있습니다.

프로젝트를 삭제하도록 예약한 사용자가 삭제가 발생하기 전에 프로젝트에 대한 액세스 권한을 잃으면(예를 들어, 프로젝트를 떠나거나, 역할이 다운그레이드되거나, 프로젝트에서 금지되는 경우), 삭제 작업은 대신 프로젝트를 복원하고 프로젝트는 더 이상 삭제가 예약되지 않습니다.

프로젝트가 삭제로 표시되면 예약된 CI/CD 파이프라인이 실행을 중지합니다.

> [!warning]
> 프로젝트 삭제를 예약한 사용자가 작업 실행 전에 소유자 역할 또는 관리자 액세스 권한을 다시 획득하면 작업이 프로젝트를 영구적으로 제거합니다.

[Rails 콘솔을 사용하여 프로젝트를 삭제](troubleshooting.md#delete-a-project-using-console)할 수도 있습니다.

## 프로젝트 아카이브 {#archive-a-project}

{{< history >}}

- Pages 제거가 GitLab 17.5에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/issues/343109)되었습니다.

{{< /history >}}

프로젝트를 아카이브하여 읽기 전용으로 만들고 향후 참조를 위해 데이터를 보존합니다.

프로젝트를 아카이브할 때:

- 프로젝트가 비활성화되고 `Archived` 배지가 표시됩니다.
- 리포지토리, 이슈, 병합 요청 및 패키지를 포함한 대부분의 기능이 읽기 전용이 됩니다.
- 포크 관계가 제거되고 포크의 열려 있는 병합 요청이 종료됩니다.
- 배포된 페이지가 사용자 지정 도메인과 함께 제거됩니다.
- 예약된 CI/CD 파이프라인이 실행을 중지합니다.
- 풀 미러링이 중지됩니다.

사전 요구 사항:

- 관리자이거나 프로젝트에 대한 소유자 역할이 있어야 합니다.

프로젝트를 아카이브하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 프로젝트 개요 페이지의 오른쪽 위 모서리에서 **조치**({{< icon name="ellipsis_v" >}})을 선택합니다.
1. **아카이브**를 선택합니다.

**귀하의 작업** 목록 보기에서 직접 프로젝트를 아카이브하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택합니다.
1. 드롭다운에서 **내 모든 프로젝트 보기**를 선택합니다.
1. **멤버** 탭에서 아카이브할 프로젝트를 찾고 세로 줄임표({{< icon name="ellipsis_v" >}})를 선택합니다.
1. **아카이브**를 선택합니다.

이 작업은 다른 목록 페이지에서도 사용할 수 있습니다.

- 예약된 CI/CD 파이프라인이 자동으로 다시 시작됩니다.

> 배포된 페이지는 자동으로 복원되지 않습니다. Pages를 복원하려면 파이프라인을 다시 실행해야 합니다.

사전 요구 사항:

- 관리자이거나 프로젝트에 대한 소유자 역할이 있어야 합니다.

프로젝트를 아카이빙 해제하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 프로젝트 개요 페이지의 오른쪽 위 모서리에서 **조치**({{< icon name="ellipsis_v" >}})을 선택합니다.
1. **아카이빙 해제**를 선택합니다.

**귀하의 작업** 목록 보기에서 직접 프로젝트를 아카이빙 해제하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택합니다.
1. 드롭다운에서 **내 모든 프로젝트 보기**를 선택합니다.
1. **비활성** 탭에서 아카이빙 해제할 프로젝트를 찾고 세로 줄임표({{< icon name="ellipsis_v" >}})를 선택합니다.
1. **아카이빙 해제**를 선택합니다.

## 프로젝트 이전 {#transfer-a-project}

{{< history >}}

- GitLab 17.7에서 [기능 플래그](../../administration/feature_flags/_index.md) `transfer_project_with_tags`를 사용하여 [도입](https://gitlab.com/gitlab-org/gitlab/-/issues/499163)되었습니다. 기본적으로 비활성화되었습니다.
- GitLab 17.7에서 [GitLab.com에서 활성화](https://gitlab.com/gitlab-org/gitlab/-/issues/499163)되었습니다. 기능 플래그가 제거되었습니다.
- 프로젝트의 비동기 이전이 GitLab 18.11에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/work_items/594575)되었으며, [기능 플래그](../../administration/feature_flags/_index.md) `groups_and_projects_async_transfer`가 있습니다. 기본적으로 비활성화되었습니다.
- GitLab 19.4에서 [일반적으로 사용 가능합니다](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/250913). 기능 플래그 `groups_and_projects_async_transfer`이 제거되었습니다.

{{< /history >}}

프로젝트를 이전하여 다른 그룹으로 이동합니다. 프로젝트 이전은 동일한 GitLab 인스턴스의 모든 네임스페이스 간에 개별 프로젝트를 이동합니다.

프로젝트를 다음에서 이전할 수 있습니다:

- 개인 네임스페이스에서 그룹으로
- 한 그룹에서 다른 그룹으로
- 그룹에서 개인 네임스페이스로

사전 요구 사항:

- 대상 그룹에 대한 유지 관리자 또는 소유자 역할입니다.
- 이전할 프로젝트의 소유자 역할입니다.
- 대상 그룹에 대해 프로젝트 생성을 활성화합니다.

> [!note]
> 보관되었거나 삭제 대기 중인 프로젝트는 이전할 수 없습니다.

프로젝트를 이전하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **설정** > **일반**을 선택합니다.
1. **고급**을 펼치세요.
1. **프로젝트 전송** 아래에서 프로젝트를 이전할 네임스페이스를 선택합니다.
1. **프로젝트 전송**을 선택합니다.
1. 프로젝트 이름을 입력하고 **확인**을 선택합니다.

전송을 확인한 후:

- 프로젝트가 비동기적으로 이전됩니다.
- 전송이 완료되거나 실패한 후 확인 이메일이 전송됩니다.
- 기존 프로젝트 URL이 새 프로젝트 URL로 리다이렉트됩니다. 새 프로젝트 URL을 보려면 페이지를 새로 고칩니다. 큰 프로젝트의 경우 이전이 완료될 때까지 기다린 후 대상 네임스페이스 아래에서 프로젝트를 볼 수 있습니다.

프로젝트를 이전한 후 다음을 확인합니다:

- 로컬 리포지토리 리모트를 새 URL로 업데이트합니다.
- 프로젝트 멤버 액세스 및 권한을 확인합니다.
- 필요한 경우 패키지 구성을 업데이트하고 다시 게시합니다.
- CI/CD 파이프라인 및 통합을 테스트합니다.
- 필요한 경우 보안 정책을 검토하고 다시 할당합니다.

관리자는 [관리 영역](../../administration/admin_area.md#administering-projects)에서 프로젝트를 이전할 수 있습니다.

### 전송되는 데이터 {#what-data-gets-transferred}

프로젝트 이전에는 다음이 포함됩니다:

- 프로젝트 구성 요소:
  - 이슈, 병합 요청 및 이슈 스레드
  - CI/CD 파이프라인 및 구성
  - 대시보드 및 위키
  - 리포지토리 코드 및 Git 기록
  - 프로젝트 액세스 토큰
- 프로젝트 멤버:
  - 직접 프로젝트 멤버 및 해당 역할
  - 보류 중인 멤버십 초대
- 자동 조정:
  - 일치하는 그룹 레이블이 없는 경우 새 프로젝트 레이블이 생성됩니다.
  - 필요한 경우 대상 그룹에서 에픽 사본이 생성되며, 프로젝트당 별도의 사본이 있습니다.
    - 동일한 에픽에 할당된 이슈가 있는 여러 프로젝트를 이전할 때 각 프로젝트에 대해 해당 에픽의 별도 복사본이 대상 그룹에서 생성됩니다.

> [!warning]
> 이전 프로세스 중의 오류로 인해 프로젝트 구성 요소 또는 최종 사용자의 종속성 데이터가 손실될 수 있습니다.

### 알려진 이슈 {#known-issues}

프로젝트를 이전할 때 다음 제한 사항을 염두에 두세요.

상속된 멤버십이 있는 프로젝트의 경우:

- [상속된 멤버십](members/_index.md#membership-types)이 있는 멤버는 대상 그룹의 멤버가 아닌 경우 액세스 권한을 잃습니다.
- 프로젝트는 대상 그룹에서 새 멤버 권한을 상속합니다.

컨테이너 레지스트리가 활성화된 프로젝트의 경우:

- GitLab.com:  프로젝트는 동일한 최상위 그룹 내에서만 이전할 수 있습니다.
- GitLab Self-Managed:  프로젝트에는 [컨테이너 이미지](../packages/container_registry/_index.md#move-or-rename-container-registry-repositories)가 포함되지 않아야 합니다.
- 1,000개 이상의 컨테이너 리포지토리가 있는 프로젝트는 이전할 수 없습니다. 자세한 내용은 [컨테이너 레지스트리 리포지토리 이동 또는 이름 바꾸기](../packages/container_registry/_index.md#move-or-rename-container-registry-repositories)를 참조하세요.

패키지 레지스트리를 사용하는 프로젝트의 경우:

- 루트 네임스페이스가 변경되면 [명명 규칙](../packages/npm_registry/_index.md#naming-convention)을 따르는 npm 패키지를 프로젝트에서 제거해야 합니다. 프로젝트를 이전한 후 다음을 수행할 수 있습니다:
  - 패키지 범위를 새 루트 네임스페이스 경로로 업데이트하고 프로젝트에 다시 게시합니다.
  - 루트 네임스페이스 경로를 업데이트하지 않고 패키지를 프로젝트에 다시 게시하면 패키지가 더 이상 명명 규칙을 따르지 않습니다. 루트 네임스페이스 경로를 업데이트하지 않고 패키지를 다시 게시하면 [인스턴스 엔드포인트](../packages/npm_registry/_index.md#install-from-an-instance)에 사용할 수 없습니다.

보안 정책이 있는 프로젝트의 경우:

- 프로젝트에 보안 정책이 없어야 합니다. 보안 정책이 프로젝트에 할당된 경우 이전 중에 자동으로 할당이 해제됩니다.

GitLab Secrets Manager를 사용하는 프로젝트의 경우:

> [!warning]
> GitLab Secrets Manager의 그룹, 하위 그룹 및 프로젝트의 모든 비밀은 [전송 중에 영구적으로 삭제됩니다](../../ci/secrets/secrets_manager/_index.md#transfer-of-a-project-or-group).

이름 또는 경로 충돌이 있는 프로젝트의 경우:

- 대상 네임스페이스에 이미 동일한 이름 또는 경로를 가진 프로젝트 또는 서브그룹이 포함된 경우 프로젝트를 이전할 수 없습니다. 여기에는 [삭제 대기 중인](#delete-a-project) 프로젝트가 포함됩니다. 충돌을 해결하려면 프로젝트를 이전하기 전에 대상 네임스페이스에서 충돌하는 항목의 이름을 바꾸거나 제거합니다.

프로젝트를 이전할 때:

- 프로젝트 [경로가 변경](repository/_index.md#repository-path-changes)됩니다. 필요한 경우 프로젝트 구성 요소의 URL을 변경해야 합니다.

### GitLab.com 프로젝트를 다른 구독 티어로 이전 {#transfer-a-gitlabcom-project-to-a-different-subscription-tier}

GitLab.com Premium 또는 Ultimate로 라이선스된 네임스페이스에서 GitLab Free로 프로젝트를 이전할 때:

- [프로젝트 액세스 토큰](settings/project_access_tokens.md)이 취소됩니다.
- [파이프라인 구독](../../ci/pipelines/_index.md#trigger-a-pipeline-when-an-upstream-project-is-rebuilt) 및 [테스트 사례](../../ci/test_cases/_index.md)가 삭제됩니다.

## 동작 메뉴를 사용한 프로젝트 관리 {#manage-projects-with-the-actions-menu}

**조치** 메뉴로 모든 프로젝트의 목록을 보고 관리할 수 있습니다.

사전 요구 사항:

- 동작을 수행하려면 필요한 [프로젝트 권한](../permissions.md#projects)이 있어야 합니다.

**조치** 메뉴로 프로젝트를 관리하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택합니다.
1. 드롭다운에서 **내 모든 프로젝트 보기**를 선택합니다.
1. **프로젝트** 페이지에서 프로젝트를 찾고 세로 줄임표({{< icon name="ellipsis_v" >}})를 선택합니다.
1. 동작을 선택합니다.

프로젝트 상태에 따라 다음 동작을 사용할 수 있습니다:

| 프로젝트 상태    | 사용 가능한 동작 |
|----------|-------------------------|
| 활성   | **프로젝트 ID 복사**, **편집**, **아카이브**, **전송**, **프로젝트에서 나가기**, **삭제** |
| 아카이빙됨 | **프로젝트 ID 복사**, **아카이빙 해제**, **프로젝트에서 나가기**, **삭제** |
| 삭제 대기 중 | **프로젝트 ID 복사**, **복원**, **프로젝트에서 나가기**, **영구 삭제** |

LDAP 그룹을 사용하여 프로젝트 액세스를 관리할 수는 없지만 다음 해결 방법을 사용할 수 있습니다.

## 프로젝트 별칭 {#project-aliases}

{{< details >}}

- 티어: Premium, Ultimate
- 제공 서비스: GitLab Self-Managed, GitLab Dedicated

{{< /details >}}

GitLab 리포지토리는 일반적으로 네임스페이스와 프로젝트 이름으로 액세스됩니다. 그러나 자주 액세스되는 리포지토리를 GitLab으로 마이그레이션할 때 프로젝트 별칭을 사용하여 원본 이름으로 해당 리포지토리에 액세스할 수 있습니다. 프로젝트 별칭을 통해 리포지토리에 액세스하면 이러한 리포지토리 마이그레이션과 관련된 위험이 줄어듭니다.

이 기능은 Git over SSH에서만 사용 가능합니다. 또한 GitLab 관리자만 프로젝트 별칭을 만들 수 있으며, API를 통해서만 만들 수 있습니다. 자세한 내용은 [프로젝트 별칭 API 설명서](../../api/project_aliases.md)를 참조하세요.

관리자가 프로젝트에 대한 별칭을 만든 후 해당 별칭을 사용하여 리포지토리를 복제할 수 있습니다. 예를 들어, 관리자가 프로젝트 `https://gitlab.com/gitlab-org/gitlab`에 대해 `gitlab` 별칭을 만든 경우 `git clone git@gitlab.com:gitlab-org/gitlab.git` 대신 `git clone git@gitlab.com:gitlab.git`로 프로젝트를 복제할 수 있습니다.
