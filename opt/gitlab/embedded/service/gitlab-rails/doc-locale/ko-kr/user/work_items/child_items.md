하위 항목은 상위 작업 항목 아래에 중첩된 작업 항목입니다. 이는 작업을 구성하고 추적하기 위한 계층 구조를 생성합니다.

하위 항목은 다음과 같을 수 있습니다:

- 상위 에픽 아래에 중첩된 하위 에픽입니다.
- 에픽에 할당된 기능이나 버그 같은 이슈입니다.
- 이슈의 하위 항목이 될 수 있는 작업입니다.

```plaintext
Parent epic
|─ Child epic
   |─ Issue
      |- Task
   |─ Issue
      |- Task
   |─ Issue
  ```

하위 항목을 사용하여 여러 계획 및 조정 문제를 해결할 수 있습니다.

다음 예시는 하위 항목이 팀이 더 효율적으로 협업하는 데 어떻게 도움이 되는지 보여줍니다.

## 부모 작업 항목에 할당된 모든 하위 항목 보기 {#view-all-child-items-assigned-to-a-parent-work-item}

하위 항목 섹션에서 에픽, 이슈, 작업이 에픽에 할당된 것을 볼 수 있습니다.

하위 항목으로 상속된 에픽, 이슈, 작업도 볼 수 있습니다.

액세스할 수 있는 에픽, 이슈, 작업만 목록에 표시됩니다.

그룹의 자식 프로젝트에 있는 에픽에 할당된 이슈를 볼 수 있습니다. 프로젝트의 표시 설정이 부모 그룹과 동일하거나 덜 제한적이어야 하기 때문입니다.

## 작업 항목 진행 상황 추적 {#track-work-item-progress}

다양한 기준을 사용하여 작업 항목의 진행 상황을 추적할 수 있습니다.

### 에픽의 이슈 개수 및 가중치 보기 {#view-count-and-weight-of-issues-in-an-epic}

**하위 항목** 섹션 헤더의 에픽에서 하위 작업 항목의 개수와 총 가중치가 표시됩니다. 작업 가중치는 총 이슈 가중치에 포함됩니다.

열린 작업 항목과 닫힌 작업 항목의 개수를 보려면 섹션 헤더 또는 각 에픽 이름 아래에서 총 개수 위로 마우스를 올립니다.

이 숫자는 볼 수 있는 권한이 없는 이슈를 포함하여 에픽과 관련된 모든 하위 작업 항목을 반영합니다.

### 에픽 진행 상황 보기 {#view-epic-progress}

{{< history >}}

- GitLab 17.1에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/issues/5163)되었습니다.

{{< /history >}}

**하위 항목** 섹션 헤더의 에픽에서 에픽 진행 상황 백분율이 표시됩니다.

하위 항목의 완료된 가중치와 총 가중치를 보려면 섹션 헤더에서 백분율 위로 마우스를 올립니다.

작업은 하위 이슈 백분율의 일부로 진행 상황 백분율에 포함됩니다.

가중치와 진행 상황은 볼 수 있는 권한이 없는 이슈를 포함하여 에픽과 관련된 모든 이슈를 반영합니다.

## 하위 항목 추가 {#add-child-items}

다음과 같이 수행할 수 있습니다.

- 다른 그룹 계층 구조의 프로젝트의 작업 항목을 포함하여 기존 작업 항목을 하위 항목으로 추가합니다.
- 새 작업 항목을 만들고 하위 항목으로 자동 추가합니다.

### 에픽에 이슈 추가 {#add-an-issue-to-an-epic}

{{< history >}}

- 하위 이슈 및 에픽의 최대 개수가 GitLab 17.1에서 5000으로 [변경](https://gitlab.com/gitlab-org/gitlab/-/issues/452111)되었습니다.

{{< /history >}}

기존 이슈를 에픽에 추가하거나 에픽에 자동으로 추가되는 새 이슈를 만듭니다.

직접 하위 이슈 및 에픽의 최대 개수는 5000입니다.

#### 에픽에 기존 이슈 추가 {#add-an-existing-issue-to-an-epic}

[다른 그룹 계층 구조](../group/epics/_index.md#child-issues-from-different-group-hierarchies)의 프로젝트에 있는 이슈를 포함하여 기존 이슈를 에픽에 추가할 수 있습니다.

새로 추가된 이슈는 **하위 항목** 섹션의 이슈 목록 맨 위에 나타납니다.

에픽은 이슈 목록을 포함하며 이슈는 최대 하나의 에픽의 하위 항목으로 설정될 수 있습니다. 이미 에픽에 연결된 새 이슈를 추가하면 이슈가 현재 부모에서 자동으로 연결 해제됩니다.

사전 요구 사항:

- 이슈의 프로젝트에 대해 게스트, 플래너, 리포터, 개발자, 유지보수자 또는 소유자 역할이 필요합니다.
- [에픽을 볼](../group/epics/manage_epics.md#who-can-view-an-epic) 수 있는 권한이 있어야 합니다. 에픽의 그룹에서 역할이 필요하지 않습니다. 에픽의 그룹 또는 해당 하위 그룹 중 하나의 프로젝트 멤버십이면 충분합니다.

에픽에 기존 이슈를 추가하려면:

1. 에픽 페이지에서 **하위 항목** 아래에서 **추가**를 선택합니다.
1. **기존 이슈**를 선택합니다.
1. 추가할 이슈를 다음 방법 중 하나를 사용하여 식별합니다:
   - 이슈의 링크를 붙여넣습니다.
   - 이슈 제목의 일부를 입력하여 원하는 이슈를 검색한 후 원하는 항목을 선택합니다. 다른 그룹 계층 구조의 이슈는 검색 결과에 나타나지 않습니다. 이러한 이슈를 추가하려면 전체 URL을 입력합니다.

   추가할 이슈가 여러 개인 경우 <kbd>Space</kbd> 키를 누르고 이 단계를 반복합니다.
1. **추가**를 선택합니다.

#### 에픽에서 이슈 만들기 {#create-an-issue-from-an-epic}

에픽에서 이슈를 만들면 에픽의 넓은 맥락에 집중하면서 작업을 더 작은 부분으로 나눌 수 있습니다.

에픽의 그룹이나 하위 그룹 중 하나에 있는 프로젝트에서만 에픽의 새 이슈를 만들 수 있습니다. 에픽의 그룹과 공유된 [프로젝트](../project/members/sharing_projects_groups.md)에서 새 이슈를 만들려면 먼저 [프로젝트에서 직접 이슈를 만든](../project/issues/create_issues.md#from-a-project) 다음 [에픽에 기존 이슈를 추가](#add-an-existing-issue-to-an-epic)합니다.

사전 요구 사항:

- 이슈의 프로젝트와 에픽의 그룹에 대해 게스트, 플래너, 리포터, 개발자, 유지보수자 또는 소유자 역할이 필요합니다.

에픽에서 이슈를 만들려면:

1. 에픽 페이지에서 **하위 항목** 아래에서 **추가**를 선택합니다.
1. **새 이슈 추가**를 선택합니다.
1. **제목** 아래에 새 이슈의 제목을 입력합니다.
1. **프로젝트** 드롭다운 목록에서 이슈를 만들 프로젝트를 선택합니다.
1. **이슈 만들기**를 선택합니다.

새 이슈가 에픽에 할당됩니다.

## 하위 항목 재구성 {#reorganize-child-items}

하위 항목을 재정렬하고 계층 구조 내에서 재구성할 수 있습니다.

### 에픽에 할당된 이슈 재정렬 {#reorder-issues-assigned-to-an-epic}

새 이슈는 **하위 항목** 섹션의 목록 맨 위에 표시됩니다. 이슈를 드래그하여 이슈 목록을 재정렬할 수 있습니다.

사전 요구 사항:

- 이슈의 프로젝트와 에픽의 그룹에 대해 게스트, 플래너, 리포터, 개발자, 유지보수자 또는 소유자 역할이 필요합니다.

에픽에 할당된 이슈를 재정렬하려면:

1. **하위 항목** 섹션으로 이동합니다.
1. 이슈를 원하는 순서로 드래그합니다.

### 에픽 간 이슈 이동 {#move-issues-between-epics}

{{< details >}}

- 티어: Ultimate
- 제공 서비스: GitLab.com, GitLab Self-Managed, GitLab Dedicated

{{< /details >}}

새 이슈는 **하위 항목** 탭의 목록 맨 위에 나타납니다. 한 에픽에서 다른 에픽으로 이슈를 이동할 수 있습니다.

사전 요구 사항:

- 이슈의 프로젝트와 에픽의 그룹에 대해 게스트, 플래너, 리포터, 개발자, 유지보수자 또는 소유자 역할이 필요합니다.

이슈를 다른 에픽으로 이동하려면:

1. **하위 항목** 섹션으로 이동합니다.
1. 이슈를 표시된 계층 구조의 원하는 부모 에픽으로 드래그합니다.

### 부모 이슈가 이동할 때 하위 항목 이동 {#moving-child-items-when-the-parent-issue-is-moved}

{{< history >}}

- GitLab 16.9에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/issues/371252)되었으며 [기능 플래그](../../administration/feature_flags/_index.md) `move_issue_children`로 명명되었습니다. 기본적으로 사용 중지됩니다.
- GitLab 16.11에서 [GitLab.com 및 GitLab Self-Managed에서 활성화](https://gitlab.com/gitlab-org/gitlab/-/issues/371252)되었습니다.
- GitLab 17.3에서 [일반적으로 사용 가능](https://gitlab.com/gitlab-org/gitlab/-/issues/371252)합니다. 기능 플래그 `move_issue_children`이 제거되었습니다.

{{< /history >}}

이슈를 다른 프로젝트로 이동하면 모든 하위 항목도 대상 프로젝트로 이동되고 이동된 이슈의 하위 항목으로 유지됩니다. 각 항목은 부모와 같은 방식으로 이동됩니다. 즉, 원래 프로젝트에서 닫히고 대상 프로젝트에 복사됩니다.

### 에픽에서 이슈 제거 {#remove-an-issue-from-an-epic}

에픽 세부 정보 페이지에서 에픽에서 이슈를 제거할 수 있습니다. 에픽에서 이슈를 제거한 후 이슈는 더 이상 이 에픽과 관련이 없습니다.

사전 요구 사항:

- 이슈의 프로젝트에 대해 게스트, 플래너, 리포터, 개발자, 유지보수자 또는 소유자 역할이 필요합니다.
- [에픽을 볼](../group/epics/manage_epics.md#who-can-view-an-epic) 수 있는 권한이 있어야 합니다. 에픽의 그룹에서 역할이 필요하지 않습니다. 에픽의 그룹 또는 해당 하위 그룹 중 하나의 프로젝트 멤버십이면 충분합니다.

에픽에서 이슈를 제거하려면:

1. 제거할 이슈 옆에서 **삭제**({{< icon name="close" >}})를 선택합니다. **이슈 제거** 경고가 나타납니다.
1. **삭제**를 선택합니다.

## 다단계 계층 구조로 작업 {#work-with-multi-level-hierarchies}

{{< details >}}

- 티어: Ultimate
- 제공 서비스: GitLab.com, GitLab Self-Managed, GitLab Dedicated

{{< /details >}}

에픽은 여러 개의 중첩된 하위 에픽을 포함할 수 있습니다. 다음과 같은 방식으로 이러한 다단계 하위 에픽으로 작업할 수 있습니다:

- 기존 에픽에 부모 에픽을 추가하여 에픽 계층 구조를 만듭니다.
- 부모 에픽의 그룹과 다른 그룹에 속하는 하위 에픽을 추가합니다.
- 로드맵에서 에픽의 하위 에픽 및 관련 마일스톤을 봅니다.
- 에픽에서 하위 에픽을 추가, 이동, 재정렬, 제거합니다.

에픽은 총 7개 수준까지 여러 개의 중첩된 하위 에픽을 포함할 수 있습니다.

### 에픽에 부모 에픽 추가 {#add-a-parent-epic-to-an-epic}

{{< history >}}

- GitLab 17.5에서 [도입](https://gitlab.com/groups/gitlab-org/-/epics/11198)되었습니다.

{{< /history >}}

에픽 계층 구조를 만들려면 기존 에픽에 부모 에픽을 추가합니다. 이는 여러 에픽 간의 관련 작업을 구성하고 추적하는 데 도움이 됩니다.

사전 요구 사항:

- 부모 에픽의 그룹 또는 하위 에픽의 그룹에 대해 게스트, 플래너, 리포터, 개발자, 유지보수자 또는 소유자 역할이 필요합니다.

부모 에픽을 추가하려면:

1. 상단 표시줄에서 **검색 또는 이동**을 선택하고 그룹을 찾습니다.
1. **계획** > **작업 항목**을 선택합니다.
1. 에픽을 선택합니다.
1. 오른쪽 사이드바의 **상위** 섹션에서 **편집**을 선택합니다.
1. 검색 상자에 부모 에픽의 제목의 일부를 입력합니다. 같은 그룹 계층 구조의 에픽만 검색할 수 있습니다.
1. 검색 결과에서 부모로 추가할 에픽을 선택합니다.

부모 에픽이 추가됩니다.

### 다른 그룹의 하위 에픽 {#child-epics-from-other-groups}

부모 에픽의 그룹과 다른 그룹에 속하는 하위 에픽을 추가합니다.

사전 요구 사항:

- 하위 및 부모 에픽의 그룹 모두에 대해 게스트, 플래너, 리포터, 개발자, 유지보수자 또는 소유자 역할이 필요합니다.
- 다단계 하위 에픽은 하위 및 부모 에픽의 그룹 모두에 대해 사용 가능해야 합니다.

다른 그룹에서 하위 에픽을 추가하려면 [기존 에픽을 추가](#add-a-child-epic-to-an-epic)할 때 에픽의 URL을 붙여넣습니다.

### 로드맵에서 하위 에픽 보기 {#view-child-epics-on-a-roadmap}

에픽에서 [로드맵](../group/roadmap/_index.md)의 하위 에픽 및 관련 마일스톤을 봅니다.

사전 요구 사항:

- 부모 에픽의 그룹에 대해 게스트, 플래너, 리포터, 개발자, 유지보수자 또는 소유자 역할이 필요합니다.

부모에서 하위 에픽을 보려면:

- **하위 항목** 섹션 헤더에서 **디스플레이 옵션**({{< icon name="preferences" >}}) > **로드맵 보기**를 선택합니다.

### 에픽에 하위 에픽 추가 {#add-a-child-epic-to-an-epic}

사전 요구 사항:

- 부모 에픽의 그룹에 대해 게스트, 플래너, 리포터, 개발자, 유지보수자 또는 소유자 역할이 필요합니다.

#### 새 에픽 {#new-epic}

새 에픽을 하위 에픽으로 추가하려면:

1. 에픽에서 **하위 항목** 섹션의 **추가** > **새 에픽 추가**를 선택합니다.
1. 드롭다운 목록에서 그룹을 선택합니다. 기본적으로 에픽의 그룹이 선택됩니다.
1. 새 에픽의 제목을 입력합니다.
1. **에픽 생성**을 선택합니다.

#### 기존 에픽 {#existing-epic}

기존 에픽을 하위 에픽으로 추가하려면:

1. 에픽에서 **하위 항목** 섹션의 **추가** > **기존 에픽**을 선택합니다.
1. 추가할 에픽을 다음 방법 중 하나를 사용하여 식별합니다:
   - 에픽의 링크를 붙여넣습니다.
   - 에픽 제목의 일부를 입력하여 원하는 에픽을 검색한 후 원하는 항목을 선택합니다. 이 검색은 같은 그룹 계층 구조의 에픽에만 사용 가능합니다.

   추가할 에픽이 여러 개인 경우 <kbd>Space</kbd> 키를 누르고 이 단계를 반복합니다.
1. **추가**를 선택합니다.

### 에픽 간 하위 에픽 이동 {#move-child-epics-between-epics}

새 하위 에픽은 **하위 항목** 섹션의 목록 맨 위에 나타납니다. 한 에픽에서 다른 에픽으로 하위 에픽을 이동할 수 있습니다. 이미 부모 에픽에 연결된 새 에픽을 추가하면 현재 부모에 대한 링크가 제거됩니다. 이슈와 하위 에픽은 함께 섞일 수 없습니다.

사전 요구 사항:

- 부모 에픽의 그룹에 대해 게스트, 플래너, 리포터, 개발자, 유지보수자 또는 소유자 역할이 필요합니다.

하위 에픽을 다른 에픽으로 이동하려면:

1. **하위 항목** 섹션으로 이동합니다.
1. 에픽을 원하는 부모 에픽으로 드래그합니다.

### 에픽에 할당된 하위 에픽 재정렬 {#reorder-child-epics-assigned-to-an-epic}

새 하위 에픽은 **하위 항목** 섹션의 목록 맨 위에 나타납니다. 하위 에픽 목록을 재정렬할 수 있습니다.

사전 요구 사항:

- 부모 에픽의 그룹에 대해 게스트, 플래너, 리포터, 개발자, 유지보수자 또는 소유자 역할이 필요합니다.

에픽에 할당된 하위 에픽을 재정렬하려면:

1. **하위 항목** 섹션으로 이동합니다.
1. 에픽을 원하는 순서로 드래그합니다.

### 부모 에픽에서 하위 에픽 제거 {#remove-a-child-epic-from-a-parent-epic}

사전 요구 사항:

- 부모 에픽의 그룹에 대해 게스트, 플래너, 리포터, 개발자, 유지보수자 또는 소유자 역할이 필요합니다.

부모 에픽에서 하위 에픽을 제거하려면:

1. 부모 에픽의 에픽 목록에서 **삭제**({{< icon name="close" >}})를 선택합니다. **에픽 제거** 경고가 나타납니다.
1. **삭제**를 선택합니다.

## 하위 항목 표시 기본 설정 구성 {#configure-child-item-display-preferences}

워크플로우에서 중요한 것에 집중할 수 있도록 **하위 항목** 섹션에 표시되는 정보를 구성할 수 있습니다.

{{< history >}}

- 하위 항목의 표시 옵션이 GitLab 18.10에서 [확장](https://gitlab.com/gitlab-org/gitlab/-/work_items/551231)되었습니다.

{{< /history >}}

워크플로우에서 중요한 것에 집중할 수 있도록 **하위 항목** 섹션에 표시되는 정보를 구성할 수 있습니다.

> [!note]
> 한 에픽이나 이슈에서 표시되는 정보를 변경하면 그룹 및 프로젝트의 모든 작업 항목에 대해 변경됩니다.

1. **하위 항목** 섹션 헤더의 오른쪽 위에서 **디스플레이 옵션**({{< icon name="preferences" >}})을 선택합니다.

   기본적으로 모든 옵션과 필드가 표시됩니다.
1. 표시된 정보를 변경하려면 다음 토글을 켜거나 끕니다:

   - 표시 옵션의 경우:
     - **닫힌 항목 표시**
   - 표시된 필드의 경우:
     - **상태**
     - **%d 담당자**
     - **레이블**
     - **가중치**
     - **마일스톤**
     - **반복**
     - **날짜**
     - **상태**
     - **차단됨/차단중**
