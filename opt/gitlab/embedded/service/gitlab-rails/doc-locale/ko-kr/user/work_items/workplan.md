{{< history >}}

- `workplan`라는 [기능 플래그](../../administration/feature_flags/_index.md)로 GitLab 19.0에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/240718)되었습니다. 기본적으로 비활성화되었습니다.
- 자율수행계획 위젯이 [변경되었습니다](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/250010) GitLab 19.4에서.
- GitLab Duo Agentic Chat에서 워크플랜을 보고 구현하는 기능이 [도입되었습니다](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/252727) GitLab 19.4에서.
- GitLab Duo Agentic Chat에서 워크플랜을 보고 구현하는 기능이 [제거되었습니다](https://gitlab.com/gitlab-org/gitlab/-/work_items/626672) GitLab 19.5에서.

{{< /history >}}

> [!flag]
> 이 기능의 사용 가능성은 기능 플래그로 제어합니다. 자세한 내용은 기록을 참조하세요. 이 기능은 테스트 가능하지만 프로덕션 사용은 준비되지 않았습니다.

워크플랜은 작업 항목에 첨부된 구조화된 Markdown 문서입니다. 작업 단위의 의도, 접근 방식 및 단계를 캡처합니다.

워크플랜은 GitLab Duo 에이전트에 합의된 사양과 작업 항목에 대한 검토 가능한 아티팩트를 제공합니다. 이 컨텍스트를 통해 에이전트는 짧은 프롬프트보다 더 많은 것을 기반으로 작업할 수 있으므로 더 정확하게 작업을 실행할 수 있습니다.

GitLab Duo로 워크플랜을 만들거나 수동으로 작성할 수 있습니다. GitLab Duo는 작업 항목 컨텍스트에서 워크플랜을 초안 작성하면 사용자가 이를 개선합니다. 그러면 에이전트는 워크플랜을 작업의 주요 사양으로 사용합니다.

워크플랜은 [GitLab Duo Agent Platform](../duo_agent_platform/_index.md)의 일부이며 사양 기반 개발 워크플로우입니다.

이슈 및 작업에 워크플랜을 추가할 수 있습니다.

작업 항목에 대해 계획을 설정하면 **자율수행계획** 위젯이 나타나고 워크플랜 상태를 표시합니다:

- **아직 생성되지 않음**: 작업 항목에 워크플랜이 없으며 하나를 만들 수 있습니다.
- **워크플랜 없음**: 작업 항목에 워크플랜이 없으며 하나를 만들 수 있는 권한이 없습니다.
- **보기 준비 완료**: 작업 항목에 워크플랜이 있습니다.

## 이점 {#benefits}

워크플랜은 의도를 구현과 분리합니다:

- 작업 항목 설명은 의도, 즉 원하는 것과 이유를 캡처합니다. 사용자는 설명을 읽어 목표를 이해합니다.
- 워크플랜은 구현, 즉 작업을 수행하는 방법을 캡처합니다. 에이전트는 워크플랜을 따라 작업을 수행합니다.

이 분리는 세 가지 이점을 제공합니다:

- 의도 보호: 에이전트는 작업 항목 설명과 분리된 필드에서 워크플랜을 반복하므로 계획이 여러 실행에 걸쳐 변경되더라도 의도가 유지됩니다.
- 계획 검토: 에이전트는 워크플랜을 생성한 후 일시 중지하므로 작업이 시작되기 전에 계획을 검토, 개선 및 승인할 수 있습니다.
- 에이전트 포커스: 워크플랜이 전담 필드이므로 계획 작업을 요청받은 에이전트는 작업 항목의 설명이나 다른 부분을 다시 쓰는 대신 해당 컨텍스트를 여기에 배치합니다.

## 워크플랜을 사용하는 시기 {#when-to-use-a-workplan}

에이전트에 작업을 제공할 계획이 있을 때 워크플랜을 사용합니다. **구현**을 선택하거나 계획을 코딩 에이전트에 직접 제공하여 사용합니다. 워크플랜은 에이전트가 작업을 실행할 때 가장 큰 가치를 제공합니다.

계획이 저장하는 것보다 더 많은 노력을 추가하는 작은 변경 사항이나 잘 이해된 변경 사항에는 워크플랜이 필요하지 않습니다.

## 작업 항목에 대해 계획 설정 {#turn-on-planning-for-a-work-item}

{{< history >}}

- GitLab 19.4에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/250010)되었습니다.

{{< /history >}}

기본적으로 **자율수행계획** 위젯과 신뢰도 점수는 작업 항목에서 숨겨집니다. 이를 표시하려면 해당 작업 항목에 대해 계획을 설정합니다.

사전 요구 사항:

- 작업 항목은 이슈 또는 작업이어야 합니다.
- 작업 항목을 편집할 수 있는 권한입니다.

계획을 설정하려면:

- 작업 항목의 우측 상단 모서리에서 **계획**을 선택합니다.

**자율수행계획** 위젯이 작업 항목에 나타나고 **계획** 버튼이 더 이상 나타나지 않습니다. 작업 항목에 대해 계획을 설정한 후에는 이를 해제할 수 없습니다.

## 워크플랜 생성 {#create-a-workplan}

작업 단위를 완료하는 방법을 설명하는 워크플랜을 생성합니다.

사전 요구 사항:

- 작업 항목에 대해 계획을 설정했습니다.
- 작업 항목을 편집할 수 있는 권한입니다.

GitLab Duo로 워크플랜을 생성하거나 수동으로 작성할 수 있습니다.

### GitLab Duo로 워크플랜 생성 {#generate-a-workplan-with-gitlab-duo}

사전 요구 사항:

- [GitLab Duo Chat](../gitlab_duo_chat/agentic_chat.md)이 설정되었습니다.

GitLab Duo로 워크플랜을 생성하려면:

1. 작업 항목의 **자율수행계획** 위젯에서 **생성**을 선택합니다.
1. GitLab Duo Chat에서 에이전트가 충분한 컨텍스트를 갖을 때까지 [Planner 에이전트](../duo_agent_platform/agents/foundational_agents/planner.md) 질문에 답합니다.
1. 제안된 계획을 검토하고 승인합니다.

계획을 승인한 후 GitLab Duo는 이를 **자율수행계획** 위젯에 작성합니다.

### 워크플랜 수동 생성 {#create-a-workplan-manually}

워크플랜을 수동으로 생성하려면:

1. 작업 항목의 **자율수행계획** 위젯에서 **추가 옵션** > **수작업으로 생성**을 선택합니다.
1. 선택 사항. 템플릿 드롭다운 목록에서 워크플랜 템플릿을 선택합니다.
1. 워크플랜 콘텐츠를 입력합니다. 편집기 간에 전환하려면 **리치 텍스트 편집으로 전환** 또는 **일반 텍스트 편집으로 전환**을 선택합니다.
1. **변경 사항 저장**을 선택합니다.

워크플랜 템플릿은 [설명 템플릿](../project/description_templates.md)이며 `.plan`로 끝나는 파일 이름을 가집니다.

## 워크플랜 보기 {#view-a-workplan}

워크플랜을 보려면:

1. 작업 항목으로 이동합니다.
1. **자율수행계획** 위젯에서 **보기**를 선택합니다.

워크플랜이 패널에서 열리고 렌더링된 콘텐츠를 표시합니다.

## 워크플랜 편집 {#edit-a-workplan}

사전 요구 사항:

- 작업 항목을 편집할 수 있는 권한입니다.

워크플랜을 편집하려면:

1. 작업 항목의 **자율수행계획** 위젯에서 **보기**를 선택합니다.
1. 패널에서 **편집**을 선택합니다.
1. 변경 사항을 만듭니다.
1. **변경 사항 저장**을 선택합니다.

변경 사항을 폐기하려면 **취소**를 선택합니다.

## 워크플랜 재생성 {#regenerate-a-workplan}

워크플랜을 재생성하여 GitLab Duo의 새 버전으로 콘텐츠를 바꿉니다.

사전 요구 사항:

- 작업 항목을 편집할 수 있는 권한입니다.

워크플랜을 재생성하려면:

1. 작업 항목의 **자율수행계획** 위젯에서 **보기**를 선택합니다.
1. 패널에서 **추가 작업** ({{< icon name="ellipsis_v" >}}) > **워크플랜 재생성**을 선택합니다.
1. GitLab Duo Chat에서 에이전트가 충분한 컨텍스트를 갖을 때까지 Planner Agent 질문에 답합니다.

GitLab Duo는 기존 워크플랜을 새 버전으로 바꿉니다.

## 워크플랜 삭제 {#delete-a-workplan}

사전 요구 사항:

- 작업 항목을 편집할 수 있는 권한입니다.

워크플랜을 삭제하려면:

1. 작업 항목의 **자율수행계획** 위젯에서 **보기**를 선택합니다.
1. 패널에서 **추가 작업** ({{< icon name="ellipsis_v" >}}) > **워크플랜 삭제**를 선택합니다.
1. 확인 대화 상자에서 **삭제**를 선택합니다.

이 작업은 실행 취소할 수 없습니다.

## 신뢰도 점수 {#confidence-score}

{{< history >}}

- GitLab 19.3에서 `workplan_score`이라는 [기능 플래그](../../administration/feature_flags/_index.md)로 [도입](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/248374)되었습니다. 기본적으로 비활성화되었습니다.

{{< /history >}}

> [!flag]
> 이 기능의 사용 가능성은 기능 플래그로 제어합니다. 자세한 내용은 기록을 참조하세요. 이 기능은 테스트 가능하지만 프로덕션 사용은 준비되지 않았습니다.

신뢰도 점수는 작업 항목이 에이전트를 실행할 준비가 얼마나 되었는지 보여줍니다. GitLab Duo는 작업 항목이 얼마나 완전하고, 명확하고, 잘 범위가 지정되었는지에 따라 점수를 매기고 신뢰도 수준에 매핑합니다.

사전 요구 사항:

- 작업 항목에 대해 계획을 설정했습니다.

작업 항목의 **자율수행계획** 위젯에서 신뢰도 수준은 **낮음**, **중간** 또는 **높음**으로 나타납니다. 신뢰도 수준은 GitLab Duo가 워크플랜을 생성하고 점수를 계산한 후에만 나타납니다.

점수를 높이려면 작업 항목 설명 및 워크플랜 단계에 요구사항, 수용 기준 및 제약 조건과 같은 더 많은 세부 사항을 추가합니다.

## 의사 결정 기록 {#decision-log}

{{< history >}}

- GitLab 19.3에서 `decision_log`이라는 [기능 플래그](../../administration/feature_flags/_index.md)로 [도입](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/249268)되었습니다. 기본적으로 비활성화되었습니다.

{{< /history >}}

> [!flag]
> 이 기능의 사용 가능성은 기능 플래그로 제어합니다. 자세한 내용은 기록을 참조하세요. 이 기능은 테스트 가능하지만 프로덕션 사용은 준비되지 않았습니다.

의사 결정 기록은 작업 항목에 대해 내린 의사 결정의 기록입니다. 각 의사 결정의 이유를 작업 항목 옆에 보관하므로 채팅이나 댓글 스레드에서 기록이 손실되지 않습니다.

의사 결정 기록은 이슈 및 작업과 이슈 또는 작업을 기반으로 하는 사용자 지정 작업 항목 유형에서 사용할 수 있습니다. 작업 항목에 의사 결정 기록을 가지려면 워크플랜이 필요하지 않습니다.

GitLab Duo는 작업을 계획하는 동안 미해결된 질문을 해결할 때 의사 결정을 기록에 추가합니다. 언제든지 의사 결정을 직접 기록할 수 있습니다.

사전 요구 사항:

- 프로젝트에 대해 최소한 계획자 역할이 있어야 합니다.

의사 결정 기록을 열려면:

- 작업 항목의 헤더에서 **의사 결정 기록** ({{< icon name="log" >}}) 을 선택합니다.

버튼은 작업 항목의 의사 결정 수를 표시합니다.

### 의사 결정 수동 기록 {#record-a-decision-manually}

{{< history >}}

- GitLab 19.5에서 [도입되었습니다](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/254465) [기능 플래그](../../administration/feature_flags/_index.md)와 함께 `decision_log`라는 이름입니다. 기본적으로 비활성화되었습니다.

{{< /history >}}

의사 결정을 수동으로 기록하려면:

1. 작업 항목의 헤더에서 **의사 결정 기록** ({{< icon name="log" >}}) 을 선택합니다.
1. 패널에서 **새 의사 결정**을 선택합니다.
1. 필드를 완성하세요. 필수 필드는 **의사 결정**, **의사 결정자** 및 **컨텍스트**입니다.
1. 선택 사항. **이유**에서 다른 옵션보다 이 옵션을 선택한 이유를 설명합니다.
1. 선택 사항. **소스 링크**에서 Slack, Google Docs 또는 GitLab과 같이 토론이 발생한 위치로의 링크를 추가합니다.
1. **의사 결정 생성**을 선택합니다.

## GitLab Duo로 워크플랜 구현 {#implement-a-workplan-with-gitlab-duo}

워크플랜이 있으면 GitLab Duo는 병합 요청으로 구현할 수 있습니다. GitLab Duo는 워크플랜을 주요 사양으로 취급하고 작업 항목 설명과 주석을 추가 컨텍스트용으로만 사용합니다.

사전 요구 사항:

- GitLab Duo Agent Platform 원격 플로우가 설정되었습니다.

GitLab Duo로 워크플랜을 구현하려면 다음 방법 중 하나를 사용합니다:

- 작업 항목의 **자율수행계획** 위젯에서 **구현**을 선택합니다.
- 워크플랜을 열고 패널에서 구현합니다:
  1. 작업 항목의 **자율수행계획** 위젯에서 **보기**를 선택합니다.
  1. 패널에서 **구현**을 선택합니다.
