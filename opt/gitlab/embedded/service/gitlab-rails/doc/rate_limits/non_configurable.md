GitLab enforces the following rate limits in the application.

| Limit                                | Rate limit                                                     | Details |
|:-------------------------------------|:---------------------------------------------------------------|:--------|
| AI Catalog bulk enable               | 10 requests each minute for each authenticated user                  | Applies to the `aiCatalogItemConsumerBulkCreate` GraphQL mutation, which [enables an agent](../user/duo_agent_platform/agents/custom.md#enable-an-agent) or [flow](../user/duo_agent_platform/flows/custom.md#enable-a-flow) in multiple projects at once. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/265715) in GitLab 19.6. |
| AI Catalog disable                   | 30 requests each minute for each authenticated user            | Applies to the `aiCatalogItemConsumerDelete` GraphQL mutation, which [disables an agent](../user/duo_agent_platform/agents/custom.md#disable-an-agent) or [flow](../user/duo_agent_platform/flows/custom.md#disable-a-flow) in a project or top-level group. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/266155) in GitLab 19.6. |
| AI Catalog enable                    | 30 requests each minute for each authenticated user            | Applies to the `aiCatalogItemConsumerCreate` GraphQL mutation, which [enables an agent](../user/duo_agent_platform/agents/custom.md#enable-an-agent) or [flow](../user/duo_agent_platform/flows/custom.md#enable-a-flow) in a project or top-level group. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/266155) in GitLab 19.6. |
| AI Catalog save                      | 30 requests each minute for each authenticated user            | Applies to the `aiCatalogAgentCreate`, `aiCatalogAgentUpdate`, `aiCatalogFlowCreate`, `aiCatalogFlowUpdate`, `aiFlowTriggerCreate`, `aiFlowTriggerUpdate`, `aiCatalogThirdPartyFlowUpdate`, and `aiCatalogItemVersionRestore` GraphQL mutations. These mutations save [agents](../user/duo_agent_platform/agents/custom.md#create-an-agent), [flows](../user/duo_agent_platform/flows/custom.md#create-a-flow), and [automations](../user/duo_agent_platform/flows/custom.md#manage-automation-conditions), or restore an earlier version of an item. The limit is shared between them. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/267093) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `ai_catalog_config_validation_rate_limit`. Disabled by default. |
| AI governance sessions               | 120 requests per minute per authenticated user per top-level group | Applies to the `aiGovernanceSessions` GraphQL field on groups and projects, which lists AI sessions for the AI Governance dashboard and the Audit events tab. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/265874) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `ai_governance_rate_limits`. Disabled by default. |
| AI model selection update            | 30 requests per minute per authenticated user                  | Applies to the `aiModelSelectionNamespaceUpdate` GraphQL mutation, which selects the models that GitLab Duo features use in a top-level group on GitLab.com. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/265318) in GitLab 19.6. |
| AI session artifact download         | 10 requests per minute per authenticated user                  | Applies to downloading an AI session's audit events as a JSON file from the session drawer of the AI Governance Audit events tab. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/265874) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `ai_governance_rate_limits`. Disabled by default. |
| AI tool rules bulk update            | 10 requests per minute per authenticated user                  | Applies to the `bulkUpdateAiToolRules` GraphQL mutation, which updates the permissions of several AI tool rules in a top-level group, or in one of its projects, at once. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/267052) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `ai_tool_rules_bulk_update_rate_limit`. Disabled by default. |
| Auto-remediation scheduler           | 1 run and 1 reschedule run per project every 5 minutes         | Applies to [dependency scanning auto-remediation](../user/application_security/remediate/dependency_scanning_auto_remediation.md) scheduler runs. GitLab skips a run over the limit and does not retry it. The next pipeline after the period starts a new run. Reschedule runs, which fill a slot freed by a dismissed update, have their own limit. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/267539) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `dependency_management_scheduler_rate_limit`. Disabled by default. |
| Changelog generation                 | 5 calls per minute per user per project                        | Applies to the `:id/repository/changelog` endpoint. The limit is shared between `GET` and `POST` actions. |
| Commit diff files                    | 6 requests per minute                                          | Applies to expanded commit diff files (`/[group]/[project]/-/commit/[:sha]/diff_files?expanded=1`). The limit applies per user for authenticated requests, and per IP address for unauthenticated requests. |
| CSV export                           | 20 requests per hour per authenticated user                    | Applies to exporting issues, work items, merge requests and requirements as CSV, in the UI and through the `workItemsCsvExport`, `mergeRequestsCsvExport` and `exportRequirements` GraphQL mutations. The limit is shared between them. Introduced in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `issuable_csv_export_rate_limit`. Disabled by default. |
| Custom dashboard writes              | 30 requests each minute for each authenticated user            | Applies to the `createCustomDashboard` GraphQL mutation, and to the `updateCustomDashboard` GraphQL mutation when the request includes a dashboard configuration, whether or not the configuration changes. Requests that update only the name or description are not counted. The limit is shared between the two mutations. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/267386) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `custom_dashboard_write_limits`. Disabled by default. |
| DAST configuration page              | 10 requests per minute per authenticated user                  | Applies to viewing the DAST configuration page (`/[group]/[project]/-/security/configuration/dast`). [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/269404) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `dast_configuration_rate_limit`. Disabled by default. |
| Delete all merged branches           | 60 requests per minute per authenticated user                  | Applies to [deleting all merged branches](../api/branches.md#delete-all-merged-branches) with `DELETE /projects/:id/repository/merged_branches` and to deleting merged branches in the UI. The limit is shared between them. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/269510) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `delete_merged_branches_rate_limit`. Disabled by default. |
| Delete a deployment                  | 500 requests per minute per authenticated user                 | Applies to [deleting a deployment](../api/deployments.md#delete-a-deployment) with `DELETE /projects/:id/deployments/:deployment_id`. Reduces the infrastructure impact of mass deployment deletions. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/243738) in GitLab 19.2. |
| FogBugz import                       | 1 triggered import per minute per user                         | Applies to triggering project imports from FogBugz. Introduced in GitLab 17.6. |
| Fork synchronization                 | 10 requests every 30 minutes for each user and project         | Applies to [updating a fork](../user/project/repository/forking_workflow.md#from-the-ui) in the UI and to the `projectSyncFork` GraphQL mutation. Requests over the limit return the error `This service has been called too many times.` in the mutation's `errors` field. In the UI, an alert shows the error. Requests are not counted when the branch is not behind the upstream default branch, or when a previous synchronization attempt found merge conflicts. |
| Group deletion                       | 60 requests per minute per authenticated user                  | Applies to [scheduling a group for deletion](../api/groups.md#schedule-a-group-for-deletion) with `DELETE /groups/:id`. Requests that use `permanently_remove` are limited separately to 10 requests per minute, because they start the deletion immediately. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/263606) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `group_and_project_delete_rate_limit`. Disabled by default. |
| GitLab for Slack app events          | 60 requests per minute per Slack workspace                     | Applies to events Slack sends to `POST /integrations/slack/events`, such as mentions and direct messages to GitLab Duo. Requests over the limit are acknowledged and dropped. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/work_items/631397) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `slack_app_workspace_rate_limit`. Disabled by default. |
| GitLab for Slack app interactions    | 300 requests per minute per Slack workspace                    | Applies to `POST /integrations/slack/interactions` and `POST /integrations/slack/options`. Requests over the limit are acknowledged and dropped. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/work_items/631397) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `slack_app_workspace_rate_limit`. Disabled by default. |
| GitLab for Slack app slash commands  | 60 requests per minute per Slack workspace                     | Applies to `POST /slack/trigger`. Slash commands over the limit are not run and receive an error message. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/work_items/631397) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `slack_app_workspace_rate_limit`. Disabled by default. |
| Merge request context commits        | 10 requests per minute per authenticated user                  | Applies to the API endpoints that [create](../api/merge_request_context_commits.md#create-context-commits-for-a-merge-request) and [delete](../api/merge_request_context_commits.md#delete-context-commits-from-a-merge-request) merge request context commits. The UI uses the same endpoints. The two endpoints share the limit. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/267499) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `rate_limit_context_commits_write`. Disabled by default. |
| Metric definitions export            | 30 requests per minute per IP address                          | Applies to [exporting metric definitions](../api/usage_data.md#export-metric-definitions) with `GET /usage_data/metric_definitions`. Authenticated requests are also counted per IP address. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/270522) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `rate_limit_metric_definitions`. Disabled by default. While the flag is disabled, requests over the limit are logged but not blocked. |
| New user accounts                    | 20 calls per minute per IP address                             | Applies to the `/users/sign_up` endpoint. Mitigates attempts to mass discover usernames or email addresses in use. |
| Note edits                           | 300 requests per minute per authenticated user                 | Applies to editing comments in the UI, through the REST API, and through the `updateNote`, `updateImageDiffNote`, and `repositionImageDiffNote` GraphQL mutations. Users excluded from the [note creation rate limit](content_creation.md#note-creation) are also excluded from this limit. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/267849) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `notes_update_rate_limit`. Disabled by default. |
| Notification emails                  | 1,000 notifications per 24 hours per project or group per user | Applies to notification emails related to a project or group. [Generally available](https://gitlab.com/gitlab-org/gitlab/-/issues/439101) in GitLab 17.2. |
| Offline transfer exports and imports | 6 requests per minute per user                                 | Applies to [offline transfer](../user/import/gitlab_instances/offline-transfer-migrations.md) exports and imports, which are limited separately. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/209344) in GitLab 19.3. |
| Project deletion                     | 60 requests per minute per authenticated user                  | Applies to [deleting a project](../api/projects.md#delete-a-project) with `DELETE /projects/:id`. Requests that use `permanently_remove` are limited separately to 10 requests per minute, because they start the deletion immediately. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/263603) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `group_and_project_delete_rate_limit`. Disabled by default. |
| Refresh billable users               | 1 request per 10 minutes per authenticated user                | Applies to [triggering a recalculation of billable users](../api/license.md#trigger-recalculation-of-billable-users) with `PUT /license/:id/refresh_billable_users`. Each request starts a full count of billable users. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/267082) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `throttle_refresh_billable_users`. Disabled by default. |
| Repository archives (per project)    | 5 requests per minute per user and project                     | Applies to [downloading repository archives](../api/repositories.md#retrieve-file-archive-from-a-repository) through the UI or the API. Requires the `archive_rate_limit` [feature flag](../administration/feature_flags/_index.md). |
| Repository blob and file access      | 5 calls per minute per object per project                      | Applies to files larger than 10 MB on the [repository blob](../api/repositories.md#retrieve-a-blob-from-a-repository) and [repository file](../api/repository_files.md#retrieve-a-file-from-a-repository) endpoints. [Introduced](https://gitlab.com/gitlab-org/security/gitlab/-/issues/1302) in GitLab 18.1. |
| Scanned resources CSV download       | 5 requests per minute per authenticated user                   | Applies to downloading the scanned resources CSV for a pipeline's DAST reports. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/268224) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `scanned_resources_csv_limits`. Disabled by default. |
| Scanned resources GraphQL fields     | 60 pipelines per minute per authenticated user                 | Applies to the `scannedResources` and `scannedResourcesCount` GraphQL fields for DAST and API fuzzing reports. Each pipeline whose scanned resources are requested counts once. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/work_items/637250) in GitLab 19.6 [with a feature flag](../administration/feature_flags/_index.md) named `scanned_resources_graphql_limits`. Disabled by default. |
| Secrets manager enablement           | 30 requests per minute per top-level group                     | Applies to the `projectSecretsManagerInitialize` and `groupSecretsManagerInitialize` GraphQL mutations, which [enable GitLab Secrets Manager](../ci/secrets/secrets_manager/_index.md#enable-gitlab-secrets-manager) for a project or group. Projects and groups in the same top-level group count toward the same limit. Requests for a project or group that already has a secrets manager are not counted. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/269629) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `secrets_manager_initialize_rate_limit`. Disabled by default. While the flag is disabled, requests over the limit are logged but not blocked. |
| Snippet creation                     | 300 requests per hour per authenticated user                   | Applies to [creating a snippet](../api/snippets.md#create-a-snippet) with `POST /snippets`, [creating a project snippet](../api/project_snippets.md#create-a-snippet) with `POST /projects/:id/snippets`, and the `createSnippet` GraphQL mutation used by the GitLab UI. The limit is shared between all three. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/251927) in GitLab 19.4. |
| Spam checks                          | 60 requests per minute per authenticated user                  | Applies when GitLab sends new or changed content to [Spamcheck](../administration/reporting/spamcheck.md) or [Akismet](../integration/akismet.md) for a spam check. This includes creating and updating issues, work items, comments, merge requests, milestones, and snippets. All of these share the limit. CSV imports of issues and work items do not count toward the limit. Requests over the limit are not saved and return an error. Does not apply when neither Spamcheck nor Akismet is enabled. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/269749) in GitLab 19.7 [with a feature flag](../administration/feature_flags/_index.md) named `spam_check_rate_limit`. Disabled by default. While the flag is disabled, requests over the limit are logged but not blocked. |
| SSH certificate authentication       | 300 failed authentication attempts per minute per IPv4 address or IPv6 `/64` subnet | Applies to SSH certificate resolution by `gitlab-sshd` for certificates whose certificate authority is not in the [`gitlab-sshd` `config.yml`](../administration/operations/gitlab_sshd_ssh_certificates.md). Only failed resolutions count toward the limit. When an address or subnet is over the limit, all certificate resolution requests from that address or subnet are rejected until the one-minute window expires. If GitLab Shell does not send a valid client IP address, the limit uses the GitLab Shell node address. IP addresses in the [failed authentication ban allowlist](https://docs.gitlab.com/omnibus/settings/configuration/#configure-a-failed-authentication-ban) are exempt. An allowlisted IPv6 address does not exempt the rest of its `/64` subnet. If the fallback GitLab Shell node address is in the allowlist, the limit does not apply. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/263054) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `ssh_certificate_authentication_rate_limit`. Disabled by default. |
| Tasks by type                        | 20 requests per minute per authenticated user per group        | Applies to the requests that load the [**Tasks by type** chart](../user/group/value_stream_analytics/_index.md#view-tasks-by-type) data and its top labels. The limit is shared between them. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/268747) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `tasks_by_type_rate_limit`. Disabled by default. |
| Update username                      | 10 calls per minute per authenticated user                     | Limits how frequently a username can be changed. Mitigates attempts to mass discover which usernames are in use. |
| Username exists                      | 20 calls per minute per IP address                             | Applies to the internal `/users/:username/exists` endpoint, which checks whether a chosen username is taken. |
| Work item bulk update                | 30 requests per minute per authenticated user                  | Applies to [bulk editing issues](../user/project/issues/managing_issues.md#bulk-edit-issues) and [epics](../user/group/epics/manage_epics.md#bulk-edit-epics) in the UI, and to the `workItemBulkUpdate` GraphQL mutation. The limit is shared between them. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/263775) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `work_item_bulk_update_rate_limit`. Enabled by default. |
| Work item deletion                   | 300 requests per minute per authenticated user                 | Applies to the `workItemDelete` GraphQL mutation. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/253621) in GitLab 19.4. [Generally available](https://gitlab.com/gitlab-org/gitlab/-/work_items/628006) in GitLab 19.5. |
| Work item hierarchy reorder          | 120 requests per minute per authenticated user                 | Applies to [reordering child items](../user/work_items/child_items.md#reorganize-child-items) in the UI, and to the `workItemsHierarchyReorder` and `epicTreeReorder` GraphQL mutations. The limit is shared between them. [Introduced](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/263802) in GitLab 19.6 [with a flag](../administration/feature_flags/_index.md) named `work_item_hierarchy_reorder_rate_limit`. Enabled by default. |
